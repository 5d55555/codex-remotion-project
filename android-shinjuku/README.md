# 新宿决战（Android）

咒术回战·新宿决战的 2D 横版对战。现在能玩：主页 → 选难度 → 战斗（五条悟 vs 宿傩；三轮、里梅、万、史上最强四个难度的宿傩都有 AI，越难越聪明，伤害和血量每高一档 ×1.1；三轮是十影宿傩，里梅开始会召唤魔虚罗、会变原身；测试模式的宿傩不动）。

## 主页

标题“新宿决战”，从上到下三个选项——开始游戏、神战模式、空置。

- 开始游戏：背景音乐从头播放并循环（反复点每次从头），进入难度选择。
- 神战模式：入口先放着，暂不开放（字是暗的），点击弹出 Toast“神战模式暂未开放”。
- 空置：点击弹出 Toast“未开放”（两个按钮 2.5 秒内的重复点击都忽略）。
- 背景音乐：`res/raw/bgm.mp3` 是用户给的原曲，原样打包（不转码、不改音量、不压缩存储）。启动后在专用线程上提前准备好；在主页、选难度、战斗之间跳转不断；整个应用切后台暂停、回前台接着播；来电等临时占用音频时暂停，结束后接着播；别的应用长期占用时停下，等下次点开始游戏。
- 帧率监视：长按右下角版本号打开/关闭。
- 背景是代码绘制的新宿夜景（`ShinjukuView`），不用图片素材。

## 选难度

从左到右五张卡（标题字号自动缩小，四个字也放得下）：三轮（三轮霞眼中的宿傩，标准难度）、里梅（里梅眼中的宿傩，困难难度）、万（万眼中的宿傩，疯狂难度）、史上最强（史上最强！噩梦难度）、测试模式（宿傩默认没有 AI）。
每个难度在 `Difficulty.java` 里有自己的 `configure(BattleConfig)`，进战斗前调用 `BattleConfig.sukunaDifficulty(0..3)`（自动对战模拟也用它，保证和游戏一样）：宿傩的 AI 聪明程度、数值档、能用的术式都在这里设置。三轮 → 里梅 → 万 → 史上最强，宿傩越来越聪明（会试探、打断念咒和瞬移、抓破绽、拉开距离和墙边跳越、骗闪避、读习惯），伤害和血量每高一档 ×1.1（连乘：1、1.1、1.21、1.331；血量 10800、11880、13068、14375）。三轮是十影宿傩：没有御厨子（解、世界斩）、没有领域、没有魔虚罗和法阵、不能变原身，十种影法术只有顎吐。里梅开始：御厨子 + 十种影法术（顎吐、魔虚罗）+ 原身。都没有领域展开（还没给素材）。详见下面“宿傩”和 `notes/宿傩AI.md`。测试模式的宿傩没有 AI，没有魔虚罗，数值 ×1。
背景图、音乐图标、五枚难度徽章、无量空处的背景由 Luna 生成（原图在 `art/`，`python3 scripts/process_art.py` 转成资源）。

## 战斗

横屏全屏，像素风（见下）。左下浮动摇杆（左半屏任意位置按下即出现），右下 体术 / 跳 / 苍 / 茈 / 赫 / 领域 / 闪避（念咒时按键外圈有进度；闪避键外圈的细线是瞬移的冷却），顶部左边返回、右边音乐开关（关掉是暂停，再点接着播），中间是难度。长按难度标签打开/关闭帧率面板（帧率、每帧逻辑耗时 ×100、绘制耗时 ×100，单位毫秒）。

场景是新宿决战原作里的设定：12 月 24 日白天的新宿，楼群被战斗破坏、街道清空（Luna 查证，见 `notes/能力与配色考证.md`）。

三轮难度的 AI：两种打法换着来——开展延贴身打，或者在中距离放顎吐牵制（十影宿傩没有解；顎吐冷却时就去贴身）；被贴身时直接开展延；血量低于 55%、离得远、没有来招时用反转术式；看到五条悟念 200% 茈、茈·最大输出或瞬移·茈的咒词会去打断（够得着就打，念咒还剩够长就放顎吐）；看到飞来的招有反应延迟地跳开或后退（有失误率）；被控住（硬直、被苍吸住、被打飞、被击倒、领域里、瞬移连段里）时不行动。里梅：反应更快、失误更少；用解试探、攒适应；学会世界斩后只在估计五条悟来不及打断时才念；进退试探；看到苍、赫、茈的念咒和瞬移的前摇就去打断（解、体术、顎吐里挑来得及的；茈·最大输出的十段咒词一定去打断）；抓长后摇；被连打时脱身；没开展延被贴身就拉开距离，墙边七成概率从五条悟头上跳过去；离开一段距离（里梅 300、万 280、史上最强 260）、他手上没在起招、赫打不过来时念「布瑠部由良由良」召唤魔虚罗（冲过来、瞬移、苍、茈都能打断，被打断 5 秒后再试）；血量跌破 35% 就变原身（魔虚罗在场时先等它，跌到 20% 或等了 3 秒就不等了）。万：再加必定墙边跳越、开着展延停在拳头边缘骗闪避和出招、等闪避的无敌过了追一拳、够不着就关展延改用解；变原身血线 30%。史上最强：再加被控后几乎不迟疑、读习惯（记下五条悟面对展延贴近时的第一反应，针对着改节奏）；变原身血线 25%。魔虚罗自己的 AI 各难度一样：往五条悟那边走，够得着出拳，再远一点挥剑。AI 用自己的随机数种子，同样的输入同样的结果。宿傩血打空后倒地，3 秒后满血站起来（魔虚罗和原身都不会回来：一局一次）；五条悟被打空血也一样（训练模式）。

### 像素风

- 整个战场（背景、角色、特效、界面的方块部分）画在 512 个虚拟像素宽的像素层上，最近邻放大铺满屏幕，所有东西在同一个像素网格上；中文字（名字、难度、按键、招式小字）在屏幕分辨率层上画，保证清楚。
- 角色是手画的像素画：`art/pixel/characters.txt` 里一个字符一个像素（调色板见文件开头），头、身体、手臂、腿分开画，按骨骼组装；头和身体只做整数像素的平移，手脚绕关节转。改完运行 `python3 scripts/pixel_art.py java` 生成 `PixelArt.java`。
- 背景是 Luna 画的像素风新宿，`scripts/process_art.py` 把它缩到 266 像素高（每块就是一个虚拟像素）、量化到 64 色、不抖动。
- 角色身体 v0.5 重画过：圆肩、收腰、更细的手脚，不再是方块（头没变）。
- 宿傩现在是伏黑惠的身体（黑色刺猬头、深色高领制服、黑色咒纹）；红眼是推测（官方没有这套造型的彩色资料）。
- 无量空处：背景换成 Luna 画的像素星空（和新宿背景同高、脚底同一行）；铺开时按行贴图（每行一条，GL 和 Canvas 结果一致），铺满后星星闪烁。

### 结构

- `core/`：纯 Java 战斗逻辑（不依赖 Android），每秒 120 tick 固定步长，完全确定（同样的输入同样的结果），热路径零分配。
- `app/`：`BattleView`（SurfaceView）+ `BattleLoop`（独立线程，自带 Choreographer，按真实时间推进 tick，渲染插值）+ `PixelScene`（全部画面，只调用 `PixelTarget` 的几个基本操作）+ `Controls`（触摸；按键事件按时间排进预分配的事件环，不合并、不丢键）+ `CutscenePlayer`（领域展开的过场视频：第二个 SurfaceView + MediaPlayer，播放器的调用都在专用线程上）。
- 宿傩的 AI（`core/SukunaAi.java`）只输出“想做什么”（`SukunaIntent`），由 `World` 检查能不能做再执行。
- 画面后端：`GlTarget`（游戏里用：GLES2，低分辨率帧缓冲 + GL_NEAREST 放大，贴图和几何共用一个着色器、攒批提交，静态图一直在显存里）；`CanvasTarget`（截图测试用，GL 起不来时兜底）。
- 设计文档：`notes/战斗架构.md`（Astra 的方案和实现时的偏差）；技术选型和审计：`notes/战斗审计.md`。

## 性能

- 纯 Java，`android.app.Activity`，不依赖 AndroidX；minSdk 26（Android 8.0），targetSdk 36。主页竖屏，选难度和战斗横屏（声明了 `appCategory="game"`，Android 16 大屏上方向锁定仍生效）。
- 战斗：逻辑和绘制都在一个独立线程上，不经过界面绘制流程；每帧零分配；GLES2 画进 512 宽的低分辨率帧缓冲再放大，图集和背景一直在显存里，每帧不上传纹理，绘制调用很少；Surface 保持原生尺寸（交给合成器缩放可能变糊）；向系统请求屏幕支持的最高刷新率（不超过 120）。卡顿后最多补 8 个 tick，不会“快进”。
- 主页背景：不动的部分（夜空、楼群、灯窗、双塔）只录一次——Android 10+ 录成 RenderNode（显示列表失效会自动重录），Android 8–9 缓存成有像素预算的位图；会动的部分每帧零分配，星星、灭窗、火星各一次 `drawPoints`。
- 自己用 Choreographer 调度，按刷新率整数分频（60/90Hz 每帧画，120/144Hz 隔一帧），刷新率运行中变化会跟着调整；只有前台、可见、系统允许动画时才动，停下时动画时间冻结。
- 背景音乐的所有 MediaPlayer 调用都在专用线程上，不碰主线程。
- 测性能请装 release 包（R8 精简、不带 debuggable）；调试包本身就会慢一些。
- 资料与审计记录：`notes/技术选型.md`、`notes/性能审计一.md`～`三.md`（主页和背景音乐）、`notes/战斗审计.md`（战斗）。
