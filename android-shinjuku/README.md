# 新宿决战（Android）

咒术回战·新宿决战的 2D 横版对战。现在能玩：主页 → 选难度 → 战斗（五条悟 vs 宿傩；三轮、里梅、万、史上最强四个难度的宿傩都有 AI，越难越聪明，伤害和血量每高一档 ×1.1；三轮是十影宿傩，里梅开始会召唤魔虚罗、会变原身；测试模式的宿傩不动）。

## 主页

标题“新宿决战”，从上到下三个选项——开始游戏、神战模式、空置。

- 开始游戏：背景音乐从头播放并循环（反复点每次从头），进入难度选择。
- 神战模式：入口先放着，暂不开放（字是暗的），点击弹出 Toast“神战模式暂未开放”。
- 空置：点击弹出 Toast“未开放”（两个按钮 2.5 秒内的重复点击都忽略）。
- 背景音乐：`res/raw/bgm.mp3` 是用户给的原曲，原样打包（不转码、不改音量、不压缩存储）。启动后在专用线程上提前准备好；在主页、选难度、战斗之间跳转不断；整个应用切后台暂停、回前台接着播；来电等临时占用音频时暂停，结束后接着播；别的应用长期占用时停下，等下次点开始游戏。
- 帧率监视：长按右下角版本号打开/关闭。
- 背景是代码绘制的新宿夜景（`ShinjukuView`），不用图片素材。

## 选难度

从左到右五张卡（标题字号自动缩小，四个字也放得下）：三轮（三轮霞眼中的宿傩，标准难度）、里梅（里梅眼中的宿傩，困难难度）、万（万眼中的宿傩，疯狂难度）、史上最强（史上最强！噩梦难度）、测试模式（宿傩默认没有 AI）。
每个难度在 `Difficulty.java` 里有自己的 `configure(BattleConfig)`，进战斗前调用 `BattleConfig.sukunaDifficulty(0..3)`（自动对战模拟也用它，保证和游戏一样）：宿傩的 AI 聪明程度、数值档、能用的术式都在这里设置。三轮 → 里梅 → 万 → 史上最强，宿傩越来越聪明（会试探、打断念咒和瞬移、抓破绽、拉开距离和墙边跳越、骗闪避、读习惯），伤害和血量每高一档 ×1.1（连乘：1、1.1、1.21、1.331；血量 10800、11880、13068、14375）。三轮是十影宿傩：没有御厨子（解、世界斩）、没有领域、没有魔虚罗和法阵、不能变原身，十种影法术只有顎吐。里梅开始：御厨子 + 十种影法术（顎吐、魔虚罗）+ 原身，v0.13 起还有领域展开「伏魔御厨子」。详见下面“宿傩”和 `notes/宿傩AI.md`。测试模式的宿傩没有 AI，没有魔虚罗，数值 ×1。
背景图、音乐图标、五枚难度徽章、无量空处的背景由 Luna 生成（原图在 `art/`，`python3 scripts/process_art.py` 转成资源）。

## 战斗

横屏全屏，像素风（见下）。左下浮动摇杆（左半屏任意位置按下即出现），右下 体术 / 跳 / 苍 / 茈 / 赫 / 领域 / 闪避（念咒时按键外圈有进度；闪避键外圈的细线是瞬移的冷却），顶部左边返回、右边音乐开关（关掉是暂停，再点接着播）和它左边的音效开关（v0.15），中间是难度。长按难度标签打开/关闭帧率面板（帧率、每帧逻辑耗时 ×100、绘制耗时 ×100，单位毫秒）。

场景是新宿决战原作里的设定：12 月 24 日白天的新宿，楼群被战斗破坏、街道清空（Luna 查证，见 `notes/能力与配色考证.md`）。

走位的顺滑（v0.14，用户反馈“AI 操作不够丝滑”）：以前宿傩、魔虚罗的速度是瞬间 0 ↔ 全速，AI 的距离带、试探、拉扯又经常走不到 0.1 秒就停或掉头，看起来一抽一抽。现在：
- 起步、停步有加减速（宿傩 0.07 秒到全速、0.05 秒停稳；魔虚罗更重，0.12 / 0.08 秒），掉头先减到 0 再加速；硬直结束时还在滑的不再一下钉住，两倍刹车停下。起跳一蹬直接全速（墙边越过五条悟头顶要这一下）。五条悟是玩家，照旧即按即走。
- 不急的变向、停步（距离带、拉扯、试探、骗招、惊惧后退）要等这一段至少走满一小段（三轮、里梅 0.083 秒，万 0.067 秒，史上最强 0.05 秒）；躲招、打断念咒、抓破绽、追闪避、脱身照样立刻变。只推迟发出去的动作，不改 AI 的想法。
- 进退试探改成一步踏进去（逼近约 80，不进 110 以内）再退回原来的距离；追闪避和魔虚罗贴近都加了滞回，不在拳头边缘一步一停。
- 走路姿势按实际速度在站姿和走姿之间过渡，倒退时身子微微后仰（以前前倾着倒退）。
- 实测（`AiSmoothness`，四个难度 × 标准脚本 × 400 局，按每分钟可走时间）：史上最强的速度突变 336 → 1 次、碎步（走不到 0.1 秒就停或掉头）170 → 40 次、来回折返 136 → 42 次；万 279 → 1、134 → 49、100 → 34（剩下那一次是撞墙被墙挡停）。胜率没变（见下）。

所有招式都有音效，全部程序合成（`scripts/game_sfx.py`，numpy / scipy，48 kHz 单声道），没有采样原作音频。声音参考是 Luna 联网查的（原作术式的听感、格斗游戏的打击层次、Android SoundPool 的做法，`notes/音效资料.md`），整套方案是 Astra 设计的（99 个编号、每条的触发条件、分层配方、混音和防糊规则、运行时架构、测试方案，`notes/音效设计.md`）。

- 声音语法：五条悟是“收拢—压缩—释放”（苍向内收的气流和拍频、赫向外张开的爆发、茈两者合拢后推出一束厚空气、无限是冲击被吸走的细玻璃鸣、黑闪在拳击后 24 毫秒出现第二道裂声）；宿傩是“划线—切断—干燥残响”（解薄而短、世界斩分结印/三段咏唱/锁定/斩开四步、空间斩更低更空、伏魔御厨子是木石共振和干金属切口，每轮斩击前有两声收拢的预警）；魔虚罗法阵转动是三下齿响后一声“咔”。
- 覆盖：五条悟的体术三连（拳、踢、上勾各一种挥空声）、苍拳、黑闪、苍（掷出、落点、吸引的循环音，出力最大更厚）、赫（推出、爆发，最大输出和瞬移后的大赫各一种）、茈（普通、200%、瞬移·茈）、无指向茈、念咒（苍蓝、赫红、茈紫三种音色，每段一个音阶）、被打断、闪避、瞬移（原地抽走、背后扣合；瞬移苍五连只有第 1、5 下带低频）、跳、落地、无限挡下、无量空处（视频之后的展开、困住宿傩时的循环、结束）、茈·最大输出 11 秒固定动作里的每个节点（托起、赫升空、宿傩斩向赫、魔虚罗挥剑、追加咏唱、相撞、爆开、收尾）；宿傩的体术、解、世界斩的四步、领域展延（开、关、持续的薄膜）、反转术式（持续的修复和声）、顎吐（结手影、飞出、电击）、召唤魔虚罗（咏唱、显现、被打断）、变原身、空间斩（起手、锁定、斩出、斩死、力竭、恢复）、伏魔御厨子（结印、展开、预警、斩中/落空、对撞的循环、崩解、结束、术式烧断恢复）；魔虚罗的显现、法阵、适应、重拳和退魔之剑的起手、被打倒；受击按伤害分轻中重；被打倒摔地的闷响（不再叠普通落地）；倒下、复活（测试模式）、开场、胜利、失败。
- 混音：背景音乐是用户给的原曲、原音量（实测 −7.5 LUFS），不压低它，所以音效靠中频的辨识度和 100–250 Hz 的谐波“重量”透出来，普通命中定在 80 毫秒 RMS −13 dBFS，其他按 Astra 的相对增益排开，峰值不超过 −1 dBFS。同一 tick 同一种攻击的受击合并成一声；黑闪、赫的爆发、茈·最大输出的爆开、伏魔御厨子的斩击、空间斩斩死都替代通用受击，苍的持续伤害不出声；连着的轻、中击只有隔开 0.15 秒的那一下带低频；每个音有最短重复间隔，按位置左右声像（±0.5）。念咒被打断时立刻掐掉咒词，补一声“断”。
- 领域展开的过场视频自带声音：放视频时战斗音效全部停下，视频结束后才响展开音；切后台、窗口被系统界面挡住时全停，回来以后持续的循环音按状态重新起（茈·最大输出的固定动作里也接得上），单发不补。
- 顶部右边音乐按钮左边是音效开关（小喇叭，关掉是暗的加斜线），记住设置；音乐、音效分开开关。
- 运行时：`SoundPoolOut`（进战斗时把全部 147 个文件预先解码，约 1.3 MB）+ `SfxDirector`（在战斗线程上每个逻辑 tick 读一遍事件和状态变化，零分配，只读世界、不影响战斗结果）。

### 像素风

- 整个战场（背景、角色、特效、界面的方块部分）画在 512 个虚拟像素宽的像素层上，最近邻放大铺满屏幕，所有东西在同一个像素网格上；中文字（名字、难度、按键、招式小字）在屏幕分辨率层上画，保证清楚。
- 角色是手画的像素画：`art/pixel/characters.txt` 里一个字符一个像素（调色板见文件开头），头、身体、手臂、腿分开画，按骨骼组装；头和身体只做整数像素的平移，手脚绕关节转。改完运行 `python3 scripts/pixel_art.py java` 生成 `PixelArt.java`。
- 背景是 Luna 画的像素风新宿，`scripts/process_art.py` 把它缩到 266 像素高（每块就是一个虚拟像素）、量化到 64 色、不抖动。
- 角色身体 v0.5 重画过：圆肩、收腰、更细的手脚，不再是方块（头没变）。
- 宿傩现在是伏黑惠的身体（黑色刺猬头、深色高领制服、黑色咒纹）；红眼是推测（官方没有这套造型的彩色资料）。
- 无量空处：背景换成 Luna 画的像素星空（和新宿背景同高、脚底同一行）；铺开时按行贴图（每行一条，GL 和 Canvas 结果一致），铺满后星星闪烁。

### 结构

- `core/`：纯 Java 战斗逻辑（不依赖 Android），每秒 120 tick 固定步长，完全确定（同样的输入同样的结果），热路径零分配。
- `app/`：`BattleView`（SurfaceView）+ `BattleLoop`（独立线程，自带 Choreographer，按真实时间推进 tick，渲染插值）+ `PixelScene`（全部画面，只调用 `PixelTarget` 的几个基本操作）+ `Controls`（触摸；按键事件按时间排进预分配的事件环，不合并、不丢键）+ `CutscenePlayer`（领域展开的过场视频：第二个 SurfaceView + MediaPlayer，播放器的调用都在专用线程上）。
- 宿傩的 AI（`core/SukunaAi.java`）只输出“想做什么”（`SukunaIntent`），由 `World` 检查能不能做再执行。
- 画面后端：`GlTarget`（游戏里用：GLES2，低分辨率帧缓冲 + GL_NEAREST 放大，贴图和几何共用一个着色器、攒批提交，静态图一直在显存里）；`CanvasTarget`（截图测试用，GL 起不来时兜底）。
- 设计文档：`notes/战斗架构.md`（Astra 的方案和实现时的偏差）；技术选型和审计：`notes/战斗审计.md`。

## 性能

- 纯 Java，`android.app.Activity`，不依赖 AndroidX；minSdk 26（Android 8.0），targetSdk 36。主页竖屏，选难度和战斗横屏（声明了 `appCategory="game"`，Android 16 大屏上方向锁定仍生效）。
- 战斗：逻辑和绘制都在一个独立线程上，不经过界面绘制流程；每帧零分配；GLES2 画进 512 宽的低分辨率帧缓冲再放大，图集和背景一直在显存里，每帧不上传纹理，绘制调用很少；Surface 保持原生尺寸（交给合成器缩放可能变糊）；向系统请求屏幕支持的最高刷新率（不超过 120）。卡顿后最多补 8 个 tick，不会“快进”。
- 主页背景：不动的部分（夜空、楼群、灯窗、双塔）只录一次——Android 10+ 录成 RenderNode（显示列表失效会自动重录），Android 8–9 缓存成有像素预算的位图；会动的部分每帧零分配，星星、灭窗、火星各一次 `drawPoints`。
- 自己用 Choreographer 调度，按刷新率整数分频（60/90Hz 每帧画，120/144Hz 隔一帧），刷新率运行中变化会跟着调整；只有前台、可见、系统允许动画时才动，停下时动画时间冻结。
- 背景音乐的所有 MediaPlayer 调用都在专用线程上，不碰主线程。
- v0.14 实测（`DrawCostTest`，真正的 World + PixelScene，史上最强对乱按两分钟）：桌面 JVM 上每帧绘制 CPU 时间平均 0.01 ms、99 分位 0.05 ms，每帧约 180 个四边形、9 批（最多 20），逻辑和绘制每帧都是零分配；逻辑每 tick 平均 0.2 µs。手机上也远在 8.3 ms（120Hz）的预算以内。
- v0.14：文字图集（各种招式名、台词，桌面上就要 85–113 ms）以前压在战斗的第一帧上，开局会顿一下；现在战斗线程一启动、Surface 还没好的时候就先做好。
- v0.14：Android 12+ 用 ADPF 性能提示（`PerfHint`）：每帧告诉系统战斗线程这一帧的工作量（逻辑 + 绘制，不含等缓冲区的时间）和刷新周期，调度器据此安排核心和频率；设备不支持就不用。负载这么轻，平时看不出差别，主要在发热降频、后台抢 CPU 时帮忙。
- 测性能请装 release 包（R8 精简、不带 debuggable）；调试包本身就会慢一些。
- 资料与审计记录：`notes/技术选型.md`、`notes/性能审计一.md`～`三.md`（主页和背景音乐）、`notes/战斗审计.md`（战斗）、`notes/帧节奏资料.md`（v0.14：帧节奏、ADPF、刷新率的官方资料核对）。

## 截图检查

容器里没有 KVM，跑不了模拟器，所以用 Paparazzi（layoutlib，和 Android Studio 预览同一套渲染）在 JVM 上把主页、角色和战斗画面渲染成图片（战斗截图用的是真正的 World 和 BattleRenderer）：

```bash
./gradlew recordPaparazziDebug   # 输出 app/src/test/snapshots/images/
```

Kotlin 和 Paparazzi 只用于这个截图测试，不进 APK（`kotlin.stdlib.default.dependency=false`；`android.useAndroidX=true` 只是因为 Paparazzi 带了 androidx.annotation）。
