# 宿傩 AI 的四个难度（v0.7）

用户的要求：“给其他难度的宿傩提供AI，不给领域，难度越高，宿傩越聪明，需要会试探和其他。”

做法：Astra 出方案（本文末尾原文）→ 实现 → 自动对战模拟逐项试（`core/src/test/.../AiExperiment.java`，每项开关单独测）→ 用没参与调参的种子验收 → Sol 审计。四个难度的宿傩血量、伤害、招式时间完全一样，只有 AI 不同。

## 每个难度会什么

参数在 `BattleConfig.AiTuning.preset(难度)`，行为在 `SukunaAi.java`。

| 难度 | 宿傩会什么 |
|---|---|
| 三轮（标准） | 基础结构：开展延贴身打，或者在中距离用解试探、攒魔虚罗的适应；看到飞来的招有反应延迟地躲；看到 200% 茈的念咒去打断。和 v0.6 完全一样。 |
| 里梅（困难） | 反应更快、失误更少；进退试探（走近一下不出手再退开）；看到念咒（苍、赫、茈）和瞬移的前摇就去打断（够得着就打，否则用解；碰到就断，被无限挡住也一样）；抓长后摇；被连打到轻拳不再硬直时想办法脱身；**没开展延时被贴身就拉开距离**（他的拳打得到我、我的拳打不到他），被逼到墙边有七成概率**从五条悟头上跳过去**；世界斩只在估计五条悟来不及打断时才念（按看到过的招推算他的冷却）；第二次反转术式留到更低的血线。 |
| 万（疯狂） | 再快一些；必定在墙边跳越；开着展延停在他拳头边缘（110–145）等一下，骗他先闪避或先出招；看到他闪避，等无敌过了、在闪避冷却好之前追一拳；展延开着却一直够不着就关掉改用解。 |
| 史上最强（噩梦） | 再快一些，被打断或被控之后几乎不迟疑；没开展延被贴身一定拉开；读习惯：记下最近 16 次“展延贴近”时五条悟的第一反应（闪避、出招、跳、退、不动），某种反应占七成以上就针对着改节奏（习惯闪避或抢招就一定先停下来骗，习惯不动就直接压上去）。 |

所有新行为每个机会只抽一次签、只排一次反应时间（不会每 tick 重抽），只看画面上看得到的东西（五条悟的动作、念咒、飞行物、他用过哪些招），不读玩家的按键。

## 附：Astra 的方案（原文）

建议采用 **“三轮保留原 AI，后三档使用同一套事件驱动战术状态机，逐档开放行为”**。四档都维持宿傩 **10800 血、原伤害和原技能时间**，不加领域展开，不加霸体或隐藏闪避。

以下是可实现的首轮参数和规则，**不是已跑出的平衡结果**。本次只读查看，没有修改文件或运行会生成文件的构建。

先说明两个核对结果：

- 当前 [Tuning.java](core/src/main/java/com/shinjuku/showdown/core/Tuning.java) 和 `World.java` 仍是旧反转术式：每次回复 450、受击或受控打断。下文按你指定的新规则设计：**170/秒，治疗 180 tick，共 255，一局最多 510，不可打断**。
- [上一轮记录](notes/宿傩平衡.md:42) 的实测五条胜率是 **基础 5%、标准 59%、熟练 59%**。熟练脚本没有明显强于标准，因此不能直接把它当成“高手玩家”。

**一、四档的行为区别**

| 难度 | 核心表现 | 相比上一档新增 |
|---|---|---|
| 三轮／标准 | 直白地开展延追打，中距离用解推进适应 | 保留现有行为；只有简单试探，没有记忆 |
| 里梅／困难 | 会停一下、退一下，看到长破绽才行动 | 进退试探、单发解观察、识别三种念咒、瞬移前摇、较长后摇；按弹道选择躲法 |
| 万／疯狂 | 能主动诱导玩家交招，再利用其空当 | 展延压近后退、延迟出拳、闪避冷却追击、落地拦截、按剩余窗口选择打断；主动关闭展延 |
| 史上最强／噩梦 | 观察同一玩家的应对，改变下一次接近和出手节奏 | 有限窗口习惯统计、方向倾向、诱饵类型切换、对惯用反击预先布置位置 |

“聪明”的可读表现应当是：玩家能发现它为什么等、为什么退、为什么这一拳晚了，而不是所有招都被瞬间破解。

**三、先建立统一的观察和执行规则**

现有 [SukunaAi.java](core/src/main/java/com/shinjuku/showdown/core/SukunaAi.java) 是多个分支同时设置布尔意图。后三档应改成“观察事件 → 排队反应 → 单一计划 → 单次动作”。

允许读取或推导：

- 双方可见位置、朝向、空地状态、动作动画、念咒阶段。
- 已观察到的动作持续了多久。
- 可见飞行物的位置、运动方向、大小、场区。
- 宿傩自己的全部资源。
- 根据**实际看到的五条出招**推算冷却；没看清的按“未知”处理。

禁止读取：

- `TickInput`、输入缓冲、按住或松开标记、玩家下一招。
- 用 `redReleased`、`purpleReleased` 提前区分尚未显现的点按／长按。
- 直接读取五条冷却来做精确反制。
- 苍尚未显示的最终落点；飞行中只用可见轨迹估计，形成吸引场后才使用其可见中心和范围。

观察到普通起手，并不等于知道玩家会继续念咒。

```text
think():
    out.clear()
    aiClock++                         // 仅 think 实际运行时推进
    更新可见动作实例、弹道轨迹、习惯统计
    更新整数冷却

    if !sukunaCanAct():
        丢弃行动计划和一次性意图
        标记 wasLocked
        return

    if wasLocked:
        设置 recoverDelay
        丢弃此前失效的破绽事件

    if recoverDelay > 0:
        return

    if 自身不是 FREE 或 sStagger > 0:
        允许观察，不发行动意图
        return

    将新事件入队：
        eventKey = 类型 + 可见实例序号
        readyAt = 首次观察时刻 + 一次抽取的 reactDelay
        accepted = 一次抽取的行为概率
        对威胁另抽一次 mistake、dodge
        不得因重复观察刷新 readyAt 或重新抽签

    从已到反应时间且仍有效的候选中选择一个计划
    复核距离、高差、冷却、剩余窗口、当前威胁
    输出最多一个动作脉冲，以及该计划允许的移动
```

优先级建议：

```text
即将命中的威胁防守／能及时消除威胁的打断
> 瞬移、念咒等时限打断
> 可命中的破绽反击
> 连打脱身
> 已提交的试探或诱招
> 治疗／世界斩／展延资源计划
> 常规接近与解
```

反应延迟从第一次看见事件开始算，不能到决策 tick 才开始，再额外等一轮。反应结束后的计划执行也不再等 `decideInterval`。

对已发出的技能等待动作状态确认；被执行器拒绝时清掉该意图，不能下一 tick 自动重发。同一机会不重新抽签；机会过期或冷却结束后才可能产生下一次机会。

**四、试探和诱招的具体规则**

**1. 进退试探：里梅开始**

触发：双方没有明显攻击威胁，距离 150–240，试探冷却结束。

```text
抽 probeChance 一次：
    前进最多 18 tick，距离到 115 即停止
    不出拳，后退最多 24 tick，距离到 180 即停止
    观察到本次计划开始后 48/60 tick 为止

若五条开始攻击、闪避或念咒：
    创建对应反应事件
    按正常反应延迟处理
若没有回应：
    回到常规接近或中距离模式
```

这是移动试探，没有无成本取消技能。墙边无法后退时，不启动这个计划。

**2. 用解点一下：里梅开始**

触发：未开展延、`ampLock==0`、解和公共攻击间隔可用、距离 240–520、高差≤70，没有更紧急事件。

```text
采用试探计划后，只发一发解
正常承担 2 tick 起手和 18 tick 收招
观察玩家是否前压、退走、闪避、跳跃、反击、无反应
这段观察时间不自动补第二发解
```

解主要用于打断和适应，不能把“无限挡住后玩家掉血”作为收益。

万和噩梦额外判断：若距上次可见法阵转动不足 120 tick，且没有打断目标，则降低继续发解的优先级。四格已满但尚未到 12 秒时，不为不存在的额外适应收益刷解。

**3. “假装开展延”：万开始**

当前没有“展延起手可取消”的机制，因此拆成两种合法表现：

- **假接近**：进入通常开展延的位置，停顿，再退开；根本不发 `amp`。
- **真开假打**：真的完成 18 tick 展延起手，靠近至 110–145，等 12–24/30 tick，不立刻出拳，再观察回应。

第二种会消耗展延持续时间。不能假播展延特效，也不能撤销已经开始的 `S_AMP_START`。

```text
展延有效 && 距离 110..145 && ampBaitCd==0：
    抽 ampBaitChance
    暂缓出拳 baitWait tick

    看见闪避：
        记录方向和开始时刻
        转入“闪避后追击”事件
    看见出招：
        能安全退出攻击范围则后退
        等可见后摇形成后再申请反击
    无反应：
        最多等待一次，然后正常压近
```

不会对空白等待每 tick 重新抽“再骗一下”。

**五、抓破绽：看什么、来不来得及、用什么**

统一采用窗口检验：

```text
反应完成后：
    earliestContact =
        自身必要等待 + 接近耗时 + 动作实际首次接触耗时

    若 earliestContact + WINDOW_MARGIN >= 对方保证无法脱离的剩余时间：
        不标记为“确定惩罚”
```

当前体术首个有效 tick 是起手之后，保守按 **9 tick**；解按 **3 tick** 预算。接近耗时只能对固定位置或明确轨迹估计，不能假定自由状态玩家会站住。

| 可见事件 | 可利用窗口 | 里梅 | 万／史上最强 |
|---|---|---|---|
| `BLUE_CHANT / RED_CHANT / PURPLE_CHANT` | 当前咏唱剩余时间 | 反应后用解打断；展延贴身可体术 | 比较关展延用解与贴身体术哪个更快 |
| `TP_WINDUP` | 总共 24 tick | 仅反应较快、解已就绪时可能打断 | 优先解；展延中仅近身且时间够才体术 |
| `FIST_WINDUP` | 总共 14 tick | 通常来不及，转防守 | 也不保证打断；主要惩罚后摇或预先站位 |
| `FIST_RECOVER` | 26 tick，当前无移动取消 | 若展延已开且及时进入窗口，体术 | 更常抓住；过期则不追发 |
| `MELEE_RECOVER` | 最早第 4 tick 可取消 | 不当成稳定长破绽 | 观察到空挥后推进；不凭完整 10 tick 后摇作保证 |
| `RED_RECOVER / PURPLE_RECOVER` | 按对应最早取消时点算 | 通常只争位置 | 必须同时排除已发出的赫／茈威胁 |
| `BLUE_RECOVER` | 只有 6 tick | 不主动追求反应惩罚 | 不虚构可抓的长后摇 |
| 正在下降，即将落地 | 没有普通落地硬直 | 不专门处理 | 预先移到落点附近，满足高度和时间才拦截 |
| 已观察到 `DODGE` | 无敌 18 tick，冷却 60 tick | 不专门追击 | 无敌结束后、预计冷却结束前尝试体术 |

这里有三个重要限制：

1. **苍拳不能靠噩梦 12–18 tick 反应稳定打断。**  
   12 tick 反应再加解的接触时间，已经超过 14 tick。高难度针对它应靠诱出空挥、站位和后摇反击；不能偷偷把专项反应改成 0。

2. **未开展延的体术、解碰到普通后摇，并不能穿无限造成伤害。**  
   没开展延时，普通后摇主要用于接近、开罩、推进适应；打断脆弱前摇是另一回事。

3. **闪避冷却中仍能跳、走、攻击和用其他合法防御。**  
   冷却仅增加进攻价值，不等于必中窗口。

闪避追击的具体规则：

```text
记录 observedDodgeStart 和实际可见移动方向
reactionReady 后：
    若仍在无敌期，等待或调整位置，不挥空拳
    预计接触时刻必须 >= start+18
    且 < start+60
    且体术届时可触及、展延仍有效
    才发一次 melee

追不上则结束追击；不能盯着不存在的冷却优势冲到场边
```

落地拦截只预测普通跳跃或已知的固定轨迹。若五条进入苍拳、瞬移或改变轨迹，原预测失效。普通落地可以立即行动，因此这是有风险的压落点，不是保证命中。

**六、防守与连打脱身**

后三档对每个新威胁先经过 `reactMin–reactMax`，成功采用防守的概率为：

```text
(1 - mistake) × dodge
```

每个威胁只抽一次。之后可以按 `defenseReplanGap` 重评路线，不重新抽成功率，不跳过首次反应时间。

候选行动固定为：

```text
原地、左走、右走、原地跳、左跳、右跳
```

用当前可见弹道和自身物理，预测未来 `defenseHorizon` 内的碰撞；优先选择不碰撞、远离苍场、不会把自己送进墙角的路线。相同评分按固定顺序打破平局。

- **赫**：能离开射程末端就退出，否则判断跳起后的身体是否真的避开弹体。普通赫速度很快，近距离看见弹体才反应，允许躲不过。
- **普通茈／200% 茈弹体**：优先可行的跳越；大茈半径更大，不能复用普通茈的跳跃时机。横向后退通常只是延迟碰撞，不能算成功躲避。
- **苍飞行阶段**：根据可见轨迹远离可能形成的吸引区；已经形成 `PULL` 后避开真实场区。已经被吸住则无行动输出。
- **无指向茈**：沿能最快离开扩张范围的路线移动；已无可行路线就接受命中，不制造无敌能力。
- **200% 茈念咒**：能赶上就解打断；不能赶上则提前规划闪躲弹体，不能一直追到发射前仍在地上。
- **瞬移前摇**：能及时接触就打断。当前瞬移会定位到宿傩背后并进入固定动作，**前摇结束后的普通跳退不能当作可靠躲法**；失败就正常承受连段。

展延中打断念咒：

```text
meleeETA = 接近耗时 + 9
offThenDismantleETA = 关闭动作调度 + 12 tick ampLock + 解接触耗时

若 meleeETA 满足窗口且更快：
    贴近体术
否则若 tacticLevel>=2 且 offThenDismantleETA 满足窗口：
    发一次 ampOff
    等实际 ampLock==0，再复核事件，发一次解
否则：
    防守预备
```

不能同 tick 同时发 `ampOff` 和解。

连打脱身：

```text
被连打期间：
    观察并计数实际可见受击
    不能行动时输出全空

恢复合法行动 + recoverDelay 结束后：
    每 escapeCd 最多申请一次脱身计划
    抽 escapeChance

    已开展延且体术能及时接触：
        反击
    未开展延且已确认本轮连续轻拳进入不再硬直阶段：
        若没有赫、苍拳、瞬移等新威胁，可尝试开展延
    否则：
        选择可行的后退或跳退
```

“三下后轻拳不再硬直”只是现有连段衰减，不保护它免受其他招式，也不允许在 `sukunaCanAct()==false` 时偷开罩。

**七、噩梦的习惯学习**

用固定数组和环形缓冲，不做机器学习，不跨局保存，不读取玩家输入。

每种情境保留最近 16 次有效观察：

```text
情境：
    展延接近
    解试探
    展延出拳

回应：
    左闪、右闪、出招、后退、跳跃、无回应
```

另保存闪避相对方向：向宿傩内侧／向外侧，避免换边后误用绝对方向。

规则：

```text
一次试探或进攻只开启一个观察窗口
同一段玩家动作只能归入一个窗口
记录窗口内第一个可见的主动回应
受控导致无法回应的样本丢弃
有效但没有回应的窗口记为“无回应”

N >= 6 且 bestCount*100 >= N*70：
    建立该情境的习惯标签

每次新计划：
    65% 采用针对策略
    35% 维持普通策略
```

针对策略：

| 观察到的习惯 | 下一次改变 |
|---|---|
| 展延一接近就闪避 | 在 110–145 停顿，先让对方闪；看见实际闪避后再追 |
| 总向同一侧／向外闪 | 接近前调整站位，保留追击路线；不提前攻击尚未发生的闪避 |
| 看到展延出拳才闪 | 不假定移动试探能骗到；混合正常出拳和延迟节奏，实际闪避后再判断追击 |
| 展延贴近就放苍／赫 | 保持在其常用出手边缘，诱出后避让，再进入真实空当 |
| 解之后总前冲 | 下一次少用解，预留展延接近计划 |
| 几乎不回应试探 | 降低空等，恢复直接压迫 |

**习惯只改变事前策略，不减掉反应延迟，也不提供未来位置。** 玩家改变打法后，旧样本会随着 16 次滑动窗口自然消失。

**八、资源管理**

**领域展延**

里梅开始，开展延前检查：

```text
自身落地、技能可用
18 tick 起手期间没有已知必中的威胁
开启后仍有足够时间接近并打出至少一拳
```

万和噩梦额外：

- 对方连续远离，超过 `ampExitFarTicks` 仍无法进入体术范围：关闭展延，恢复解和适应路线。
- 有长咏唱可打断，关闭后用解明显更快：按上面的分阶段计划关闭。
- 展延剩余时间不够支撑接近＋体术首次接触：不再无意义追拳。
- 不能以反复开关规避 12 tick 术式锁和关闭后 240 tick 冷却。

**世界斩**

第一次和后续必须分别评估。当前第一次起手就消耗束缚机会，打断不退；后续则有 144 tick 咏唱。

```text
候选条件：
    已解锁、冷却结束、落地、未展延、ampLock==0
    在设定距离内
    无已知弹体会在起手期间命中
    五条没有正在进行、能及时打断自己的可见动作

估计五条“若立刻采取行动，最快何时能打断”
未知资源按可用处理
若这个时间 <= 世界斩起手 + worldSafetyMargin：
    拒绝本次机会

否则每个合格机会只抽一次 worldChance
未采用则至少等 worldRecheckGap
```

估计应考虑瞬移前摇、赫／茈前摇与飞行时间，不能只算跑过来打拳。

使用倾向：

- 首次 48 tick：优先真正安全的中距离；确认方向稳定，不为了抢第一次而近身白送。
- 后续 144 tick：优先已观察到关键远程和瞬移刚消耗、且足够远的时机。
- 五条普通后摇普遍远短于 144 tick，不能把后续世界斩当通用后摇惩罚。
- **骗掉一次闪避不足以保证世界斩命中**：对方仍能跳，而且闪避冷却比咏唱短。

严格筛选可能让高难度世界斩次数减少，这是合理结果。对当前会精准跳预警的脚本，不应为提高命中率偷偷缩短预警或改变锁定规则。

**反转术式**

新规则每次最多回 **255**，起手＋治疗＋收招共 **240 tick＝2 秒**。

```text
剩余次数>0、冷却结束、未展延、ampLock==0、落地
缺血 >= 255
血线满足本次使用阈值
每 rctRecheckGap 最多重新考虑一次
```

新 AI 还应检查：

- 没有正在命中的高伤害弹体或瞬移前摇。
- 当前可见攻击和最早接近时间估计，治疗期间是否可能吃到超过收益的伤害。
- 万和噩梦可在低于旧距离门槛时治疗，但必须有已观察到的资源空当；不能因“不可打断”就迎着 1700 伤害茈回血。

“不可打断”建议落实为**治疗流程独立于受击动作**：受击、被吸、领域不会取消已经合法启动的治疗；但仍正常扣血、击退和受控，KO 停止治疗。领域中不得新开治疗，也不能借治疗恢复行动权。这样才不会把“不可打断治疗”误做成霸体。

**九、BalanceSim 胜率目标与调参顺序**

先保持 [GojoBot.java](core/src/test/java/com/shinjuku/showdown/core/GojoBot.java) 三套策略不变。下表是采用新反转规则后的首轮验收目标，全部指**五条胜率**：

| 五条脚本 | 三轮 | 里梅 | 万 | 史上最强 |
|---|---:|---:|---:|---:|
| 基础 | 3–10% | 2–8% | 0–5% | 0–4% |
| 标准 | 55–65% | 40–50% | 25–35% | 12–22% |
| 熟练 | 55–70% | 42–57% | 28–43% | 15–30% |

基础脚本本来已经只有约 5%，没有足够空间体现四档差距，不值得围绕它强行拉开百分比。标准和熟练才是主要比较轴；也不强求每个种子下更高难度都赢。

用现有 [BalanceSim.java](core/src/test/java/com/shinjuku/showdown/core/BalanceSim.java) 的 `report(..., tweak)` 接入四套配置，未来验证时：

- 调参集：种子 0–999，四难度×三脚本，共 12000 局。
- 留出集：1000–1999，冻结参数后再验证。
- 90 秒有效时间、首次 KO 停止；超时单独统计，不从胜率分母删除。
- 每档超时目标低于 5%。
- 统计置信区间；1000 局时，50% 附近约有 ±3 个百分点抽样误差。

新增关键指标：

```text
瞬移前摇：可打断机会数 / 尝试数 / 成功数
念咒：可打断机会数 / 成功数
试探：次数 / 实际诱出动作数 / 后续有效命中数
体术：打在闪避无敌期的次数
防守：有可行路线的机会数 / 实际成功数
展延：开启次数 / 零有效命中次数
世界斩：机会拒绝原因 / 起手 / 打断 / 斩出 / 命中
治疗：实际总治疗量 / 治疗期间承受伤害
```

现有脚本不能验收全部行为：它们不会覆盖丰富的试探回应、苍拳、习惯改变；领域内念 200% 茈时宿傩没有行动权，也不能拿它检验打断能力。另加固定输入场景验证这些行为，**不修改三套脚本来美化胜率**。

调参按以下顺序：

| 偏差 | 优先调整 |
|---|---|
| 高难度反而更弱 | 先查试探空等、追闪避是否追不上、是否过度关展延；降低 `probeChance/ampBaitChance` |
| 五条胜率过高 | 先提高合法破绽利用率、减少无效世界斩，再调 `punishChance/interruptChance` 和接近策略 |
| 五条胜率过低 | 先降低瞬移打断率和抓破绽率，再增加失误；最后才延长一般反应 |
| 基础几乎全败、标准合适 | 接受脚本能力下限，不动血攻补偿 |
| 噩梦读习惯收益过大 | 降低 `learnExploitChance`，提高最少样本数 |
| 超时或长时间拉扯 | 缩短空等和拉距离计划，增加正常进攻机会；不先增加伤害 |

**十、接入风险与验证重点**

1. **不能只改参数。**  
   旧结构缺少事件去重、单一计划、习惯状态和 `ampOff` 输出。建议保留三轮旧路径，新建战术路径，共用技能执行器。

2. **现有多个意图会互相覆盖。**  
   `World` 实际按关闭展延、体术、解、开展延、世界斩、治疗的顺序接收。新 AI 应先选唯一动作，不能设置多个布尔值后指望执行器理解战术优先级。

3. **旧概率会迅速趋近必选。**  
   “每 6 tick 有 65% 概率用世界斩”连续评估五次，至少选中的概率已超过 99%。新概率必须按事件／机会抽一次。

4. **旧计时有不同单位。**  
   `modeTimer` 按决策次数递减，修改 `decideInterval` 会同时改变换打法频率；新模式时间统一为有效 tick。命中停顿期间 `World.tick` 仍增加，AI 倒计时应跟随实际逻辑推进，不能混用。

5. **观察不能被自身出招阻断。**  
   旧 AI 在自身非 `FREE` 时提前返回，会错过飞行物和对手动作开端。新结构先观察后判断能否行动；动作执行中只能积累信息，不能取消自己的收招。

6. **威胁不能只取第一个。**  
   旧 `threatId()` 按固定顺序返回一个威胁。新 AI 应同时评估赫、茈、苍、无指向茈，按预计碰撞时间选择；否则躲赫时可能跳进苍。

7. **性能可以严格有界。**  
   六条候选路线、最多四类场景威胁、最长 90 tick 预测，每 6–12 tick 重评即可；固定数组，无每 tick 对象分配，不复制完整 `World` 搜索未来输入。

8. **确定性不仅是种子。**  
   固定候选顺序、平分裁决、抽签次数和事件序号；所有计时与计数用整数。位置预测复用当前物理，若量化采用固定规则。AI 继续使用独立 RNG，不影响黑闪 RNG。

9. **新治疗要同步更新统计。**  
   170000 毫血/秒不能用单个整数每 tick 治疗值精确表达，应使用整数余数累计。治疗期间同时受伤时，现有“正 HP 差”统计会漏算治疗，需累计实际治疗事件或独立计数器。

10. **验收规则边界。**  
    固定输入回放必须复现；不同隐藏输入但相同可见观察应产生相同 AI 意图；受控时输出全空；前摇打断要测窗口边界；普通解始终不能伤害无限；已经提交的世界斩和展延不得免费取消。
