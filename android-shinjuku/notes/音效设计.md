# 技能音效设计（v0.15，Astra）

下面是 Astra 的设计稿原文。落地时的取舍（和稿子不一样的地方）：

- 响度：稿子的基准（普通中等命中 −23 dBFS RMS、运行时再 −6 dB）在原音量的原曲（实测 −7.5 LUFS、峰值过满）下会被完全盖住，用户又要求不压低音乐，所以基准提到 −13 dBFS（80 ms 窗口 RMS），各音效之间的相对增益照稿子，峰值限在 −1 dBFS。
- 不另开音频线程：SoundPool 的 play/stop 直接在战斗线程上调（调用很快，不分配 Java 对象）；过场开始时同一个线程先全停再通知主线程放视频，顺序天然保证。
- 结构型做成单独的编号（例如 RED_FIRE / RED_FIRE_MAX / RED_FIRE_TP），共 98 个编号、145 个文件；循环音存 16 位 WAV（ffmpeg 的 libvorbis 会丢掉末尾不满一块的采样，循环接不上）。
- 落地：LAND 事件的落地速度普通跳也有 600–720，按 800 分轻重（稿子把 LAND 都当重落地）。
- 声像用平衡律（居中两边都是原音量），范围 ±0.5。

**《新宿决战》技能音效实现设计稿｜Astra**

本稿以当前 `Events.java`、`World.java`、`Fighter.java`、`PixelScene.consumeEvents()`、`BattleLoop.java` 和 `Bgm.java` 为准。全部音效离线原创合成；运行时纯 Java、SoundPool；不修改战斗判定，不修改 BGM 文件、播放音量或做 BGM ducking。以下是设计文档，没有修改任何文件。

**一、声音风格与响度基准**

五条悟的声音语法是“收拢—压缩—释放”：

- 苍：向下收口的窄带气流、干净但有拍频的谐波；重量来自 160–240 Hz。
- 赫：短暂压缩后向外张开的噪声，瞬态明确，尾巴迅速收掉。
- 茈：苍的收拢与赫的张力结合，发射和命中分开；等级越高，结构越复杂，而不是无限加响。
- 无限：冲击被吸走的细玻璃鸣，没有实体格挡的低频重击。
- 黑闪：拳击瞬态后约 24 ms 出现第二道裂声，形成可辨认的“断层”。

宿傩的声音语法是“划线—切断—干燥残响”：

- 解：薄、短、近乎没有飞行尾音。
- 世界斩：结印、三段咏唱、锁定、切开四个清楚阶段。
- 空间斩：更低、更空的前摇，锁定提示更明确；斩出仍保持短，不做普通爆炸。
- 御厨子：木石共振、干金属切口；每轮预警与斩下能够在音乐中分别辨认。
- 十影：粗糙影流与非整数金属泛音。魔虚罗法阵的“咔”是独立识别标志。

像素风体现在短包络、少量阶梯扫频和明确节拍；不把整套声音做成持续的低位深失真。

| 声音等级 | 相对普通中等命中 |
|---|---:|
| 持续环境、领域底床 | −18～−12 dB |
| 起手、移动、咏唱 | −10～−5 dB |
| 轻命中 | −4 dB |
| 中命中 | 0 dB |
| 重命中 | +2 dB |
| 普通术式释放 | 0～+2 dB |
| 最大输出、黑闪 | +3 dB |
| 空间斩、茈最大输出爆发 | +4 dB |
| 开场、结算 | −5～−2 dB |

这里的 dB 是**经过统一校准后的资产播放增益**，不是把每个文件分别峰值归一化后随意相加。校准参考为 `hit_medium` 最强 80 ms 窗口的 RMS；基准资产建议约 −23 dBFS RMS、峰值不超过 −10 dBFS。短点击不为了追齐 RMS 而强行放大。

共享母版：

1. 去 DC；二阶高通 75 Hz，四阶低通 7.2 kHz。
2. 重量主体放在 160–240 Hz，同时保留 320–720 Hz 泛音；不依赖超低频。
3. 身份与预警信息放在 700 Hz–4 kHz；3–5 kHz 噪声层比中频主体低 4–8 dB。
4. 离线软饱和后使用 1 ms lookahead、45 ms release 限幅；单资产最终真峰值不超过 −3 dBTP。
5. OGG 编码后重新解码、复测真峰值，超限则降低资产增益再编码。
6. 运行时 SFX 总增益初值 −6 dB；再按手机实听校准。SoundPool 没有可供这里使用的 SFX 总线限幅器，因此靠声部预算与保守增益避免叠加过载。
7. **不能保证原音量 BGM 加任意 SFX 后的系统混音绝不削波**。验收时只调整 SFX，不能以此为由降低音乐。

**二、事件解释与表格约定**

以下缩写只用于文档：

- `E(type,k,v)`：`Events.type / kind / value`。`*` 表示该字段不参与筛选。
- `G/S/M`：五条悟／宿傩／魔虚罗。
- `→STATE`：该角色从其他状态进入该状态。逐个逻辑 tick 检查，不从渲染帧推断。
- 所有未特别列出的无 `kind` 重载事件，其 `kind=0`。
- `X`：发生点的屏幕横坐标声像；`F`：循环跟随所属角色或场景对象；`C`：居中。
- `X→X`：瞬移起点与终点分别定位，详见混音规则。
- 时长单位秒；重复间隔单位 ms；音高列是 SoundPool `rate` 范围。
- 优先级：0 装饰、1 动作、2 命中／重要状态、3 危险预警／决定性节点。
- “变体”中的“结构型”按机制确定选择，不随机；随机变体才使用音频自己的 RNG。
- 下表共 **60 个逻辑音效编号**。结构型导出为后缀文件，例如 `gojo_melee_swing_jab_01.ogg`。同一个编号允许多种确定的结构型，不要求一种机制独占一个资源。

必须按代码解释的字段：

| 事件 | 实际含义 |
|---|---|
| `CAST` | `kind=Attack.*`；`value=0` 普通、`1` 最大苍／最大赫／咏唱世界斩、`2` 200% 茈、`3` 首次束缚世界斩、`4` 瞬移前摇、`5` 茈最大输出固定动作开始 |
| `RED_FIRE / RED_BURST` | `kind=0/1/2` 分别普通／最大输出／瞬移大赫；`value` 是方向 |
| `PURPLE_FIRE` | `kind=0/1/2` 分别普通／200%／瞬移茈；`value` 是方向 |
| `CHANT` | `kind=BLUE_FIELD/RED/PURPLE/PURPLE_MAX`；`value` 是段号；`−1` 打断。`BLUE_FIST,−1` 也用于部分苍拳、瞬移前摇取消 |
| `SLASH` | `kind=DISMANTLE/WORLD_SLASH/SPACE_SLASH`；`value` 是斩线终点 x，**不是阶段** |
| `DAMAGE` | `value` 是显示伤害；苍是累计展示伤害，不能作为连续打击触发源 |
| `HIT` | `value` 和 `kind` 都是攻击种类，不含伤害大小 |
| `DOMAIN_CUTSCENE` | `value=castId`；领域种类读 `world.cutsceneKind` |
| `CINE` | `value=CINE_*`；只有追加咏唱的 `kind` 是段号；`CINE_SLASH.kind` 是终止 x |
| `SPACE` | `kind=±1` 方向；没有 `value=2` 的斩出事件，斩出走 `SLASH` |
| `SHRINE` | `value=SHRINE_*`；只有 `SHRINE_SLASH.kind` 表示命中／落空／作废 |
| `ADAPT` | `kind=0` 转格、`1` 学会世界斩、`2` 适应无限；`value=adaptPoints`，不要自行把它当转动次数 |

补充触发规则：

- **苍拳释放**：`CAST,k=BLUE_FIST,v=0` 不是统一可靠的“拳头击中”信号，不配命中声。进入 `FIST_ACTIVE` 时复用 `blue_launch` 普通型，−5 dB；真正接触由 `DAMAGE` 或 `BLACK_FLASH` 决定。
- **普通苍、最大苍**：以 `BLUE_SPAWN/BLUE_LAND` 为释放和落点权威；`CAST,k=BLUE_FIELD,v=0/1` 不再叠一份释放。
- **普通赫、茈起手**：`CAST,k=RED/PURPLE,v=0` 不重复触发 `gojo_hold`。`CAST,PURPLE,2` 与 `PURPLE_FIRE,1` 同次释放只响后者。
- **瞬移苍五连**：用 G 当前 `TP_BLUE` 状态下的 `DAMAGE,k=BLUE_FIST` 计数。每次进入 TP_BLUE 清零；五次命中都保留瞬态，第 1、5 次保留 body。
- **无事件的动作取消**：前一 tick 为可持续起手，当前已退出，且本 tick 没有合法释放／咏唱接续／瞬移接续事件，则停止该 owner 的起手音。只有 `hitstun` 增加、`sStagger` 从 0 变正或存在明确打断事件时播放 `cast_break`；普通松手点放不播放。
- **宿傩被打断硬直**：`sStagger:0→正` 与同 tick WORLD_CHANT/SUMMON/SHRINE 打断去重。硬直期间不循环呻吟，结束不另加提示。
- **倒地**：角色 `downTicks>0` 且本 tick 接地时播 `fighter_down` 接地型；KO 入状态时播战败型。魔虚罗死亡以 `MAHORAGA_GONE` 为主，避免与 KO 双播。
- **反转术式**：当前代码治疗不可因普通受击而中断。不能见 `hitstun>0` 就停 RCT；以事件、存活及有效治疗状态判断。
- **跳跃边沿**是保守识别；若同 tick 跳起又被击飞，只保留命中，不追补跳声。

**四、每条音效的离线合成配方**

先定义参数明确的辅助记法。它们是离线 Python 辅助函数，不是要求运行时合成。

```python
# d/a/r 均为秒；全部以 SR=48000 输出。
# 所有随机层显式 seed，不依赖 sfx.py 的全局 rng。

N(d, lo, hi, a=.002):
    burst(d, lo, hi, seed, a)

C(d, lo, hi):
    crack(d, lo, hi, seed)

S(d, f0, f1, a=.003):
    sweep(f0, f1, d) * env(int(d*SR), a, d*.8)

W(d, f0, f1, a, r):
    band_sweep(d, f0, f1, width=.6, seed=seed) \
        * env_ar(int(d*SR), a, r)

P(d, f, ratios, amps, decay, a=.003):
    partials(f, ratios, amps, d, decay, detune=0, seed=seed) \
        * clip(T(d)/a, 0, 1)

B(d, f0=220, f1=160):
    # 手机可听的重量：基频 + 二、三次谐波。
    S(d,f0,f1) + .35*S(d,2*f0,2*f1) + .15*S(d,3*f0,3*f1)

R(x, wet, tail):
    verb(x, wet, ir(.18, 25, seed, bright=3500), tail)

D(x, t):
    # 前面补 int(t*SR) 个零；用于层间延迟。

M(*layers):
    mix(*layers)
```

以下表中每行均按“瞬态 T／主体 B／尾音 R”执行；`drive` 是 `sat` 的参数。先混层、再饱和、再加表中混响。最后补齐或裁至清单时长，单发末端加 8 ms 余弦淡出；点击至少加 1 ms 淡出。没有列混响即 `wet=0`。

循环用单独函数：

```python
L(d, freqs, amps, lo, hi, noise_amp, am_hz, am_depth):
    t = T(d)
    tones = sum(a*sin(2*pi*f*t) for f,a in zip(freqs,amps))
    bed = noise_amp * filt(noise(len(t),seed),'bp',(lo,hi),2)
    return (tones + bed) * (1-am_depth/2 + am_depth/2*cos(2*pi*am_hz*t))
```

循环频率尽量选满足整周期的值；噪声层用 30 ms 等功率首尾交叉处理，输出周期长度按处理后的实际帧数登记。循环不叠大厅混响、不在文件首尾做淡入淡出；由运行时控制起停包络。

生成随机变体时只改变噪声 seed 和主体频率 ±1.5%，包络时长最多 ±4%；预警、咏唱段序与固定演出不改节奏。种子可固定为 `1000 + 37*音效编号 + 变体号`。

同类升级的区别：

- **轻／中／重受击**：不是只放大。瞬态长度约 7/9/12 ms，body 45/85/140 ms；重击才有明显尾音。
- **普通／最大苍**：加宽吸流与拍频，落点更厚，循环只提高约 3 dB，不持续轰鸣。
- **普通／最大赫**：主体稍长，延后裂声增加层次；高频不继续抬高。
- **普通／200% 茈**：增加双音张力与中低频持续时间，主增益只提高 1 dB。
- **瞬移茈**：近距离起音更快、尾巴比 200% 短；1900 伤害不需要再次加响。
- **茈最大输出**：优势来自完整的节点节奏；接触、爆开、残响分开。不能导出一条 11 秒巨型音效塞进 SoundPool。

**六、混音、合并与防糊规则**

**同一次命中只指定一个主要冲击声。**

按单 tick 的完整事件批次仲裁，先收集，再决定播放，不能看到第一个 `DAMAGE` 就立刻播放：

1. 黑闪取代对应接触的 `hit_*`。
2. `RED_BURST` 负责红球爆发；同次 `DAMAGE,k=RED` 只保留极轻的接触层，默认直接省略。
3. `CINE_BLAST` 取代该 tick 全部 `PURPLE_MAX` 受击主声。
4. `SPACE,v=3` 取代该次空间斩的通用重受击；斩出声仍保留。
5. `SHRINE_SLASH` 负责该轮主切口，`DAMAGE,k=SHRINE_SLASH` 不另响。
6. 苍的累计 `DAMAGE` 完全不触发 `hit_*`；持续吸引由循环表达。
7. `HIT` 不再单独配通用命中，避免和 DAMAGE 双播。
8. 普通茈穿透两人：同 tick 同攻击种类的通用受击合并为一声，位置取受击位置平均值、等级取最大值，不叠两份低频。
9. `INFINITY_BLOCK` 与 `cast_break` 可以同时出现：前者说明被无限挡下，后者说明自己的准备被打断；两者总增益各减 2 dB。

现有事件没有 target ID 和 attack instance ID。当前方案对同 tick 同种类多目标音做有意合并，不通过“离事件最近的角色”猜受击对象。若以后要求逐目标独立定位，再考虑扩展事件，而不是现在新增字段。

声部上限：

| 声部组 | 上限 | 溢出处理 |
|---|---:|---|
| 危险预警、锁定 | 2 | 优先保留空间斩／世界斩锁定；同 owner 新段替换旧段 |
| 通用命中 | 3 | 同 tick 合并；新重击替换旧轻击 |
| 技能释放／爆发 | 3 | 保留新瞬态，先停旧尾音 |
| 起手／移动 | 2 | 丢最低优先级旧声 |
| 咏唱 | 2 | 每角色最多 1 |
| 环境循环 | 2 | 对撞优先，其次无量／苍；展延最低 |
| UI／结算 | 1 | 新结算替换旧音标 |

SoundPool 配 `maxStreams=16`；导演层目标不超过 12–14 路，留少量切换余量。不能把 SoundPool 的自动抢占当成唯一声部管理。

连击 body：

- 五条三连：第 1 下保留轻 body，第 2 下无 body，第 3 下保留。
- 连续普通体术密度超过每秒 6 下时：后续每三次只留一次 body。
- 瞬移苍五连：第 1、5 下完整，第 2–4 下无 body。
- 黑闪始终用完整专用声；同组旧 body 在 12–20 ms 内淡掉。
- 魔虚罗重拳、重剑和重技能不跟随普通体术计数，但全局 90 ms 内最多启动一个重 body。
- 适应完成和转格同 tick：保留 `adapt_complete`，不叠 `wheel_click`。

重复间隔按实际播放时钟检查，避免一帧补多个 tick 时同时倾倒旧声音；逻辑层仍记录每个触发，合并结果单独记录原因。重要危险预警不同阶段不能被一个粗暴的“同类冷却”吞掉。

命中停顿：

- 在产生命中的 `world.step()` 返回后立即读取该 tick 的事件。
- 不等下一次画面动画、不等 hitstop 结束。
- 当前 `World.step()` 在 hitstop 时仍会增加 `tick`，但动作逻辑不推进；不得把 `world.tick` 误当 `stateTick`。
- 音频不随 hitstop 暂停。黑闪第二裂声、命中 body 通过离线样本内部偏移完成，不用运行时定时器。
- 多 tick 补帧无法恢复已经错过的真实播放时刻；同帧合并近邻低优先级音，禁止延迟排队“补完”。

长音中断：

- 每个循环／长单发登记 owner、用途及 streamId。
- 咏唱打断时立即取消待播段，当前段 8–12 ms 淡出并停止，播 `cast_break`。
- 视频／后台必须立即 `stop()` 所有流；这里不等待淡出完成。
- 正常领域结束可 30–50 ms 淡出；新重技能可压低**其他 SFX 尾音** 4 dB、约 120 ms，绝不操作 BGM。
- 不用 `autoResume()` 复活已暂停的旧攻击声；恢复只重建仍然成立的状态循环。

声像：

```text
p = clamp(2 * screenX / viewportWidth - 1, -0.65, 0.65)
theta = (p + 1) * π / 4
left  = gain * cos(theta)
right = gain * sin(theta)
```

`screenX` 使用不含震屏偏移的相机投影；循环每帧平滑更新，约 60 ms 追随。单发发出后保持声像，避免高速镜头让声音晃动。

瞬移离开音定位事件 `x`，到达音定位事件 `value`；两者同 tick 启动，到达样本内部留约 12 ms 前置空白。手机单扬声器仍能听见两个不同音色，不能把辨识依赖在左右声道上。

**七、运行时架构与接入位置**

建议分四层：

| 类 | 职责 |
|---|---|
| `SfxCatalog` | 编译期整数编号、资源 ID、变体索引、时长、优先级、声部组、增益常量 |
| `SfxDirector` | 纯 Java、无 Android 依赖；读取 World 事件和状态，做去重、段序、循环目标状态与声部决策 |
| `SfxCommandRing` | 预分配单生产者／单消费者环，传递 play/stop/volume 与生命周期 epoch |
| `SoundPoolSfx` | 专用音频命令线程持有 SoundPool、加载状态、逻辑 voice handle 到 streamId 的映射 |

播放接口可使用纯基本类型：

```java
interface SfxSink {
    void play(int cue, int variant, int voice, int priority,
              float gain, float pan, float rate, int epoch);
    void stop(int voice, int epoch);
    void stopAll(int epoch);
    void setVolume(int voice, float gain, float pan, int epoch);
}
```

`voice` 是预分配槽位句柄，含 generation，避免旧 stop 误停复用后的新声音。

SoundPool 初始化：

```java
new SoundPool.Builder()
    .setMaxStreams(16)
    .setAudioAttributes(new AudioAttributes.Builder()
        .setUsage(AudioAttributes.USAGE_GAME)
        .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
        .build())
    .build();
```

SoundPool 适合预加载短音效，播放失败会返回 0；加载完成应通过监听器确认。单音效解码大小约 1 MB 上限、流优先级及 `rate` 行为按官方 API 实现，不能按 OGG 压缩体积判断是否超限。[Android SoundPool 官方文档](https://developer.android.com/reference/android/media/SoundPool)

`BattleLoop` 接入：

```java
// 一帧开始，固定数组清空计数，不创建集合。
director.beginFrame(frameTimeNanos);

while (accNs >= TICK_NS) {
    // 原有输入读取……
    director.beforeStep(world); // 保存缺少事件的状态边沿
    world.step(input);
    director.afterStep(world);  // 每个 tick 都读自己的事件游标
    input.clearEdges();

    if (world.cutscene) break;
}

if (world.cutscene) {
    director.suspendForCutscene(world.castId);
    // 先停止并建立音频屏障，再通知主线程开启视频。
} else {
    director.endFrame(world, frameTimeNanos); // 合并、限额、提交
}
```

`beforeStep()` 只保存所需原始字段：角色 state/stateTick、onGround、vy、hitstun、downTicks、sStagger、cine 等。`afterStep()` 使用自己独立的 `seenEvents`，不能共用或推进 `PixelScene` 的游标。

过场结束的 `BattleLoop.endCutscene()` 内：

1. 先验证本次 `castId`，旧回调不改变 SFX 状态。
2. 调用 `world.endCutscene(castId)`。
3. 若确实退出过场，立即消费新产生的 `DOMAIN_OPEN/SHRINE_OPEN/SHRINE_CLASH` 事件。
4. 若 Activity 仍后台，不播放这些瞬态，只更新游标与恢复目标。
5. 前台恢复时重建仍有效的循环，过期的展开瞬态不补播。
6. 视频出错或超时同样走一次该路径，不重复展开音。

视频静音屏障：

- `suspendForCutscene()` 递增 epoch，清除待播命令，设置音频 worker 的门控。
- 音频线程停止所有登记流后确认 `stoppedEpoch`。
- 收到确认后主线程才启动视频；战斗线程不忙等。
- 使用预先创建的回调／Runnable，不在热路径新建。
- 已经送往设备缓冲区的极短尾巴无法通过 Java API 召回；必要时在确认后给视频首音预留一段经过设备测试的缓冲空档。不得让战斗循环继续播放来“掩盖”切换。

注意：`world.cine!=CINE_NONE` **不是**视频门控条件；11 秒固定动作继续播放 CINE 音效。

零分配与线程约束：

- 环容量建议 256；所有字段分离为 `int[]/float[]/long[]`，初始化时分配。
- 指令发布使用单写者索引与 `volatile` 发布顺序；消费完成前生产者不能覆盖。
- stop-all／门控使用独立 epoch 通道，不允许因为播放环满了而丢失。
- 热路径禁止 `ArrayList`、`Map<Integer,…>`、字符串文件名、字符串日志、临时 lambda、流式 API、装箱和临时随机对象。
- UI 文案、资源表、dB 转线性表、声像查找表提前准备。
- 音频 RNG 使用独立 `int` 状态的 xorshift32，种子固定但不引用 `CombatRng`；关闭音效也不影响战斗 RNG。
- 音频线程不读取 World；只消费基本类型命令。
- 战斗线程不等待加载、播放返回、音频线程或资源 I/O。
- 环满时先丢装饰／移动音，累计整数诊断计数；不阻塞。
- `SoundPool` 内部和 Android 框架可能自行分配；“零分配”验收范围应明确为**项目的战斗线程触发路径**。将 SoundPool 调用放专用线程可以隔离这部分风险。
- worker 可使用预创建线程和 `LockSupport.unpark()` 唤醒；不要每条音效 `Handler.post(new Runnable...)`。
- 普通音量淡出由音频线程扫描固定 voice 数组完成，不为每个淡出分配任务。

生命周期：

| 情况 | 处理 |
|---|---|
| 切后台、Surface 不可用 | 立即门控并停止所有流；保留设置，不保留播放进度 |
| 回前台 | 快照现有状态，初始化边沿缓存；仅恢复有效循环，旧单发不追补 |
| 音效关闭 | 同停止流程；继续消费事件，避免重新开启后倾倒积压 |
| 音效重新开启 | 恢复状态循环；仍在合法前摇中的长音可从合适结构段开始，不从头补整段召唤 |
| 退出战斗 | epoch 作废；停止所有流；退出应用再 release SoundPool |
| 重新对局 | 清事件游标、动作计数、声部槽、演出阶段；新 epoch |
| 音频焦点丢失 | 门控 SFX；恢复条件满足后按状态重建 |

现有 `Bgm` 自己持有音频焦点。建议把焦点所有权提到应用级共享协调器，BGM 与 SFX订阅同一前台／焦点状态，避免两个播放器互相申请焦点。音乐开关只控制音乐意图；关音乐后仍可有技能音。

保持 `Bgm.VOLUME=1.0f` 和原来的原曲播放语义，不给 BGM 添加任何技能触发音量代码。系统自身的焦点处理不属于技能混音控制。

界面：

- 顶部右侧原音乐按钮保留，在其左侧新增 **音效按钮**。
- 两个触控框均至少 48×48 dp，间隔 8 dp；音乐最右，音效向左排列。
- 音效图标用代码绘制“短扬声器＋两条声波”；关闭时斜杠，底部加小字“音效”，避免与音符图标混淆。
- 开／关状态记入 `SharedPreferences`，键 `sfx_enabled`，默认开启。
- 偏好读写在 UI／非战斗线程；战斗线程只接收 boolean 状态。
- 音效开关不控制领域视频声音，也不控制音乐；无障碍描述明确“技能音效开／关”。
- 关闭操作本身静音；开启可播一次 −12 dB 的短 `ability_restore`，仅在非视频且前台时。

加载未完成：

- 进入难度选择即预加载，不能在命中时 `load()`。
- 每个资源有 `LOADING/READY/FAILED` 整数状态；监听器通过安全发布更新状态。
- 未 ready 的单发直接略过，不等、不积压、不晚播。
- 循环标记为 desired，资源 ready 后若状态仍成立再开始。
- 主体资源加载失败不影响对局；可对普通受击使用已 ready 的中击替代，危险预警不可用无关喜庆音代替。
- `play()` 返回 0 则清理该逻辑 voice，循环在受限重试间隔后再尝试；单发不重试。

**八、资产体积与构建要求**

离线工具可继续使用现有 numpy/scipy；Android 包中不加入它们。输出只包含 OGG 和生成好的整数资源表。

- 默认 48 kHz、单声道 Vorbis。
- 先用约 48–64 kbps 等效质量编码；噪声复杂的黑闪、斩击若出现水声，再局部提高质量。
- 长音最长 2 秒；48 kHz、mono、PCM16 为 192,000 字节。即使用 float32 估算也约 384,000 字节，明显低于单文件 1 MB。
- 目标全部结构型、随机型、无body型总时长不超过约 90 秒；加容器头开销后，设构建硬门槛 **2.5 MB**。
- 文件大小以实际导出结果为准，不能用目标码率推测验收。
- 总解码 PCM 内存另测，压缩包小不等于运行内存小。
- 资源不足时依次减少随机变体、删除装饰尾音、共用关闭音；不削减锁定预警和主要招式身份。
- OGG 循环必须以实际 SoundPool 解码结果做接缝测试；不能只检查 Python WAV 循环无缝。

**九、自动测试与设备验收**

`SfxDirector` 不依赖 Android，JVM 用假的 `SfxSink` 记录整数指令。测试中允许分配；生产导演代码仍保持固定数组。

| 测试 | 操作与断言 |
|---|---|
| 事件分派真值表 | 枚举本稿所有合法 type/kind/value；CAST 4 不误当普通释放，RED kind 2 不误当伤害值，SPACE 没有虚构的 value 2 |
| 体术三连 | 脚本点按三次，检查 swing 结构型 0/1/2；挥空只有 swing，无 hit |
| 苍拳与下砸 | 长按体术、按住跳跃点体术；检查前摇、释放、命中、取消，不重复 CAST 命中 |

**十、不新增的音效、事件与取舍**

本版**不要求新增 Events 类型**。现有事件加逐 tick 状态边沿足够实现主体方案；固定动作缺少独立事件的升空、接近阶段由 `cineTick` 阈值驱动，引用 `Tuning` 常量。

有意省略：

- **五条领域结印独立音**：`DOMAIN_CAST` 与 `cutscene=true` 在同次调用中成立，结印已经进入自带声音的视频；叠加会违反过场静音要求。
- **领域视频内展开音**：完全使用视频原声。表中 open 是返回游戏画面后的短接续音。
- **御厨子持续斩击底噪**：每半秒已有预警和斩击，不再叠全天候刀雨循环。
- **每 tick 苍伤害声音**：会糊成噪声，也不对应独立打击。
- **普通冷却完成音**：只保留术式烧断、空间斩力竭结束这两个机制状态提示。
- **脚步、持续喘息、角色惨叫**：不属于本次技能音效必要信息，且会占用快速连击空间。
- **捌、竈、宿傩黑闪**：当前游戏未实现，不建虚假触发器。
- **仿原作语音**：咏唱采用原创合成音节，文字内容由现有画面承担。

主要风险与处理：

- **音乐遮蔽**：原音量音乐可能很密。优先改预警频率、包络和重复结构，其次降装饰 SFX；不能改 BGM。
- **状态边沿漏掉同 tick 起止**：对已经有事件的动作一律以事件为准；状态只补起手和移动。无声的极短取消可以接受，不能因此改变战斗执行顺序。
- **事件缺少角色／攻击实例**：当前通过同 tick 合并解决；将来若新增同种攻击并发机制，再扩充事件元数据。
- **SoundPool 延迟、循环与抢占**：依赖预加载、短资产和明确 voice 管理；必须真机测，不把 API 的“低延迟”理解为零延迟。
- **过场音频严格隔离**：停止所有流并建立视频启动屏障；设备已经缓冲的声音只能靠经过测量的短空档处理。
- **原声音乐与视频同播的总响度**：维持现有行为。这里的 SFX 系统只负责自己的静音边界，不接管音乐或视频音量。
