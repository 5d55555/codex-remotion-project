# 领域对撞与简易领域（v0.17，Astra 设计、Luna 查证）

用户的要求（原话）：

1. “对方已经在领域展开的播放动画中，没办法进行领域展开 修复这点”
2. “可以通过长按屏幕来在对方展开领域时展开领域，通过分镜同时处理动画。”
3. “长按跳跃键且身处敌方领域内，则能开启简易领域（简易领域没有冷却，自己领域展开始简易领域直接没，自己没领域的时候还能用）”

下面先写落地情况和与设计稿不同的地方，后面附 Luna 的原作查证要点和 Astra 的设计稿原文。

## 落地情况

### 反制（长按屏幕）

- 宿傩的伏魔御厨子过场（`domain_shrine.mp4`）从准备到播完都能长按：主指按住 450 ms、移动不超过 24 dp。底部提示：`长按屏幕 · 展开无量空处`；按住时 `正在展开` 加手指周围的进度环；不能用时显示 `无量空处冷却中 · X.X 秒` 或 `当前状态无法展开`。
- 手势在主线程（`CutscenePlayer.Curtain`）识别，成功后经 `BattleView.tryCounter` → `BattleLoop` 投到战斗线程，由 `World.tryCounterDomain(castId)` 再校验一次（资格同设计稿 B 表：冷却、已有领域、倒下、倒地、浮空、被抓、固定演出、硬直、已分胜负都不行；另外瞬移连段、茈·最大输出这类固定动作里也不行。正在念咒或起手时可以反制：手上的咒词按“松手”作废，锁定照旧，但过场里不发“断”的声音）。接受时五条悟进 `DOMAIN_CAST`、`castId` 加一（宿傩那段视频的旧回调全部对不上）、过场种类换成 `CUTSCENE_CLASH`；结果投回主线程，`CutscenePlayer.counterResult` 释放旧播放器、新建一个放 `domain_clash.mp4`。所有媒体回调都先查 `stale(mp)`。
- 原片播完时手势还按着、或战斗线程的结果还没回来：保留幕布和末帧等结果，不提前结束过场；被拒绝就按原流程结束。
- 宿傩视频起不来：显示 1 秒 `伏魔御厨子正在展开` 兜底卡片，期间仍可长按；对撞片起不来：直接结算，两个领域照样一起开。
- 对撞片放完：`World.endCutscene` 的 CLASH 分支一次建好两个领域（`shrineTicks = 720`、`shrineNext = 60`、魔虚罗停手、`domainTicks = 960`、`clashTicks = 240`、刷新必中，各发一次 `SHRINE_OPEN`、`DOMAIN_OPEN`、`SHRINE_CLASH`），之后就是原有的 2 秒对撞规则：拆掉御厨子无量空处生效，拆不掉无量空处被外面击碎（冷却 40 秒）。不另给奖励时长。
- 宿傩不会反过来在五条悟的过场里反制（用户没要求，设计稿也建议不做）。

### 对撞过场 `domain_clash.mp4`

- `scripts/render_clash.py` 按设计稿 A 的七个镜头从两段原片合成：7.5 秒、1920×1080、60 fps、H.264，音轨按混音表加一记合成的接触音。成片响度 −11.4 LUFS、真峰值 −2.7 dBTP（和伏魔御厨子原片的 −11.3 LUFS 一样响；最初按 −2 dBTP 做，AAC 编码后冒到 −0.3，改成 −3 dBTP 目标）。只重混音轨：`python3 scripts/render_clash.py --audio-only`。
- 结尾停在两个领域接触的一刻，不出现外壳破裂、不出胜负字幕：胜负留给战斗里的 2 秒对撞。

### 简易领域（长按跳跃）

- 只在伏魔御厨子真的开着时（`shrineTicks > 0`，御厨子没有半径，整片战场都算在里面）、五条悟站在地上能动、自己没有领域时生效。不看无量空处冷却（用户定）。
- 这时跳跃键改成：短按松手才跳（照常进 14 tick 输入缓冲），按满 30 tick（0.25 秒）开简易领域、松手不跳；按着跳跃时点体术是下砸苍拳（优先），点闪避或术式就放那一招、这次不跳也不开圈；中途挨打或被抓就作废（不补跳）；御厨子在按住时结束，就只剩松手跳。领域外按下就跳，和以前一样。
- 开成时以五条悟的位置为圆心，在地上画一个半径 120 的圈（固定，不跟人走）；圈里能走、能出招。人在地上、在圈里时，御厨子每一轮必中斩击不伤五条悟、不击退、不加硬直，圈被削掉一层（`SHRINE_SLASH.kind = 3`）；三层削完圈碎掉，马上可以再按 30 tick 重开（没有冷却，用户定）。宿傩硬直那一轮作废时不削层。只挡必中斩击：宿傩的体术、解、世界斩等照常结算。
- 圈立刻消失的情况：自己领域展开开始（普通展开和长按反制都算，用户定）、御厨子结束或崩解、三层削完、跳起来或被打离地、走出圈、倒下、倒地、被抓、对局结束。
- 画面：地上一个米白色椭圆（28 段线，浅蓝内缘），开圈 0.1 秒从中心长出来，三个小刻线是剩余层数，削一层时边缘往里一缩；碎掉时一圈散开的线和火花；正常收圈只淡出。刚开时五条悟头上 0.6 秒的「简易领域」。跳跃键外圈：按住时是蓄满进度，圈开着时是剩余层数。
- 音效（`scripts/game_sfx.py`，`--only=sfx_simple_open_0,...` 只重写这几个文件）：开圈 −7 dB 的清鸣和收拢气流，削一层 −9 dB 的短裂（两种变体），碎掉 −5 dB 的三下干裂加下扫；正常收圈复用无量空处的消散；被挡住的斩击只有很轻的落空声，不放受击和无限的声音。
- AI 没改：宿傩不读简易领域（设计稿 C 的结论），手动攻击照样能打到圈里的五条悟。御厨子全吃大约 330–400 血，按得及时可以基本全挡掉，这是“没有冷却”的直接结果，没有暗中加御厨子的伤害。

### 和设计稿不同的地方

- 没给 `TickInput` 加 `jumpUp` / `jumpCancel`：松手就是 `jumpHeld` 变成 false（触摸被系统取消也当松手）。
- 「简易领域」字样显示 0.6 秒（稿子 42 tick），和其他头顶字一样长。
- 碎圈特效用的是一圈火花加散开的线，不是 12 段分开飞散。

### Sol 审查后修的（v0.17）

- 按着跳跃时在命中停顿里点了别的招（例如领域），停顿结束后招照常放，但按着的跳跃没作废，过场放完松手会自己跳：取消判断挪到 `latch()`（停顿里也收），`clearInputs()` 也清掉按着的跳跃。
- 反制能把念咒、固定动作直接盖成领域展开，咒词残留、没有锁定：念咒和起手改成按“松手”作废（`breakChant(false)`，不发事件），瞬移连段、茈·最大输出里不接受反制。
- 宿傩视频准备得慢时，换片后才到的旧首帧通知会提前打开幕布：首帧和画面比例的主线程回调都带上当时的 castId，对不上就丢掉。

### 测试

- `core/.../CounterSimpleTest`：反制后一次建好两个领域直接对撞、没反制只开御厨子、资格（冷却、错 castId、重复请求）；跳跃的短按、长按、领域外照常、按着跳点体术是下砸苍拳；三轮挡下后碎掉并能重开、无量空处冷却中照样能开、自己领域展开时消失、走出圈或跳起来消失、御厨子结束时消失、对撞中不能开。
- `SfxDirectorTest`：简易领域的开、削、碎各响对的那一声，正常收圈不响碎裂；反制对撞在两个领域都开好之前一声不出。

## Luna 的原作查证要点

### 先给设计结论

第225话的核心不是两个领域“谁的特效更大”，而是**两人几乎同时结印、领域正面对撞，五条的闭合结界从外侧遭到宿傩无结界领域的攻击**。做过场时建议把双方的结印和领域名交叉剪辑，最后用一个横向构图让无量空处与伏魔御厨子同时占据画面；随后让神龛从外侧劈开五条领域的壳，明确交代胜负机制。

来源方面，漫画可从 [VIZ 官方章节目录](https://www.viz.com/shonenjump/chapters/jujutsu-kaisen)查第225话；动画已有部分领域演出的官方资料，但我没有查到官方公布过“新宿决战领域对撞”的动画 PV 或预告。官方动画官网可核对已播集数与内容：[《咒术回战》动画官网集数页](https://jujutsukaisen.jp/episodes/index.php)。

### 1. 第225话：同时领域展开与分镜要点

#### 手印、台词与领域名

- **五条悟**结的是单手印。粉丝和资料整理常称“帝释天印”，但这个具体名称并非第225话台词确认的设定；建议游戏内当作考据标签使用，不要把它作为角色明确念出的词。
- **宿傩**结的是双手印，常被称作“阎魔天印”，同样属于对手印原型的考据命名，并非这段对话里明确报出的术式名称。
- 两人喊出的启动词是**“领域展开”**（領域展開）。领域名分别是**“无量空处”**（無量空処）和**“伏魔御厨子”**（伏魔御廚子）。原作画面主要以领域展开的动作与领域视觉呈现名称；如果游戏把领域名做成大字字幕，应视为视觉设计，而不是一定要让角色再念一遍。
- “帝释天印／阎魔天印”的资料整理可参考[手印汇总](https://eiga-manga.com/entry/jujutsu-ryoikitenkai)，但它属于二手考据，不是官方术语表。

#### 领域对撞规则怎么呈现

领域内的必中效果会在两方领域重叠时互相抵消；决定领域优劣的因素包括领域本身的精度和结界条件。这里两人的领域在内部较量，但**宿傩的伏魔御厨子不靠封闭结界把目标关进去**，因此可以从外部攻击五条闭合领域的外壳。第225话的要点是这项结构优势：五条的必中在交叠处被抵消，外壳却承受来自外侧的斩击。

可直接转成玩法提示：

1. **内层对抗**：两边领域在交叠区域产生相互抵消的纹理、噪点或闪白。
2. **外层弱点**：让伏魔御厨子的斩击落在五条领域的外壳上，而不是表现成两种必中在内部互相“砍”。
3. **打破结界**：外壳先出现裂纹，再被连续斩击撕开；随后切到五条承受必中效果。

#### 漫画分镜可借鉴什么

漫画的节奏重点是双方的**平行展示与快速对照**：两人结印、领域展开、领域结果互相切换，最后把焦点落到五条领域外壳受击的差异上。它不是把一方完整施法播完、再从头播放另一方；剪辑应让观众感觉两人同一瞬间出手。

为了像漫画那样读得清楚，可用以下顺序：

- 交替给五条和宿傩的结印近景，剪辑间隔逐渐缩短。
- 两人同声“领域展开”，画面短暂并置。
- 领域名与领域景象分别出现，再切到两领域的相遇。
- 用一个宽画面表现内部对撞，再给五条领域外壳被斩的特写。

“两人背对背”很适合作为格斗游戏的定格或角色立绘构图，但应标注为**游戏化重构**，不要当成第225话的逐格复刻。这个章节的重点构图是同时施术和领域相撞，并不是必须出现背靠背画面。

### 2. 简易领域：设定和玩法适配

#### 来历与“弥虚葛笼”的关系

简易领域是**新影流**的反领域术式，由芦屋贞纲创立。它的用途是削弱领域的必中效果，弥虚葛笼则是更早的反领域术式；可以把简易领域理解为后来的术式发展脉络之一，但两者不是同一个招式，也不该把“简易领域是弥虚葛笼的升级版”当作逐字设定。

简易领域通常在使用者周围形成一小片范围，常见视觉是地面上的圆形边界。它主要对抗领域的必中机制，**并不让使用者免疫领域里的普通攻击或其他手动攻击**。进入范围的术式也可能被削弱，但这不等于完全消除术式。

资料整理可参阅[简易领域条目及其章节引用](https://jujutsu-kaisen.fandom.com/wiki/Simple_Domain)，并用 VIZ 的第225话及后续章节核对原作上下文。

#### 姿势、移动与出招

**没有一条适用于所有使用者的通用规则，规定简易领域必须全程站桩。**新影流不同用法受使用者能力、设定条件和绑定的誓约影响：

- 三轮霞的简易领域有“脚离开原位即解除”的限制，站定能换取反击优势。
- 日下部能把简易领域用于自动反击，攻击和防御可以结合。
- 所以游戏里可把三轮做成“站桩反击圈”，把日下部做成“可移动或带自动拔刀反制的圈”；不要把三轮的限制套到所有角色身上。

#### 领域攻击会不会把简易领域打掉

会。简易领域不是永久盾，它可以被强力领域逐渐削弱、剥离。新宿决战后段，虎杖等人用简易领域抵挡宿傩的伏魔御厨子；虎杖的简易领域在领域持续期间被剥掉，随后斩击命中。第258话的表现很适合游戏化为“领域持续压制 → 防护圈裂开或缩小 → 角色受击”。[VIZ 官方章节目录](https://www.viz.com/shonenjump/chapters/jujutsu-kaisen)列有相关后续章节；[第258话情节概述](https://daddyjim.com/jujutsu-kaisen/manga-chapter/Chapter-258)也记录了简易领域被剥离的过程。

#### 持续时间与重复使用

原作没有给简易领域设定统一的固定秒数；持续力取决于使用者和对手领域的输出。虎杖等人在第258话的简易领域撑过了宿傩不完整领域持续期间的大部分时间，最终仍被剥离。因此游戏里适合做成**可消耗的防御状态或耐久条**，而不是固定为某个“原作秒数”。

原作也有简易领域被打破后再次展开的表现，包括五条在与宿傩交战时的用法。设计上可以允许再次施放，但用冷却、资源消耗或受击中断控制频率。

#### 五条会不会用简易领域

会。五条在与宿傩的领域战中使用简易领域自保；对应漫画在第226话及后续对决。相关能力条目也列出五条的用法和对应章节：[五条悟能力资料](https://jujutsu-kaisen.fandom.com/wiki/Satoru_Gojo)。

因此，若游戏要给五条配置简易领域，**不需要另编理由**：它可以作为五条在领域对抗中的防御选项。若你想让角色更贴近其标志性风格，可以将它做成短暂抗必中效果的应急技，而不是常规主力招式。

### 3. MAPPA 动画的领域展开演出参考

动画已有的领域演出可以给你镜头节奏参考，但不能当成新宿这场对决的预告片替代品：

- **五条对漏瑚、涩谷篇**：官方动画集数页可用于确认相关动画内容；官方页面在此：[TV动画官网](https://jujutsukaisen.jp/episodes/index.php)。这类演出适合参考“动作或手势启动 → 领域名 → 空间感转换”的节奏。
- **宿傩对魔虚罗、涩谷篇**：这是宿傩领域展开较完整的动画参照，适合提取“先给宿傩结印，再让领域景观压进画面”的演出方法。第41集的剧情可由[官方集数页](https://jujutsukaisen.jp/episodes/index.php)核对；此处不把非官方剪辑视频当作官方 PV。
- **官方预告现状**：我查到的是动画官网集数与既有动画信息，没有找到新宿决战“五条 vs 宿傩同时领域展开”的官方动画 PV。建议在企划文件中标注“未来动画化的风格参考”，而非“官方 PV 分镜”。

适合像素格斗的转换方式：每次空间翻转时保留角色剪影或地平线作为视觉锚点，避免连续全屏特效让观众丢失左右位置；两领域同时出现时，可以用左右分屏逐渐合并为全屏对撞，再切到外壳受击的局部特写。

### 4. 6–9秒“同时展开”过场分镜建议

素材时长分别是五条7.45秒、宿傩13.3秒，不能简单完整串联：总长会超过目标。推荐截取关键动作，并用像素化转场补足节奏。下面按约8秒设计：

| 时间 | 画面与剪辑 |
|---|---|
| 0.0–0.8秒 | 新宿废墟宽镜头，两人对峙；环境声压低，只留风声或低频脉冲。 |
| 0.8–1.7秒 | 快切五条拉衣领、宿傩结印，交替两次；最后半秒停在双手印对单手印的对照。 |
| 1.7–2.5秒 | 两人几乎同时喊“领域展开”；画面左右分屏，字幕同时落下。不要先播完一方再播另一方。 |
| 2.5–3.5秒 | 五条眼睛特写、结印；对切宿傩结印。两边背景各自开始变形，领域名短促闪出。 |
| 3.5–4.7秒 | 依次闪出“无量空处”的冷色空间与“伏魔御厨子”的神龛、獠牙和骷髅；用左右分屏维持同时性。 |
| 4.7–5.7秒 | 分屏撕开并合成一个横向全景，两个领域在同一格里相撞；撞击瞬间一帧白闪，随后环境音抽空。 |
| 5.7–6.9秒 | 切五条领域外壳特写：外侧连续出现黑红斩痕，裂纹从画面边缘往内爬。 |

### B. 长按反制规则

**结论：宿傩过场从开始到结束都允许尝试；长按屏幕 0.45 秒成功后立即提交五条展开，替换为对撞片。结束时同时建立双方领域，沿用现有 2 秒对撞，不增加奖励时长。**

#### 资格与手势

以下额外限制属于本稿补充，目的仅是避免死亡、倒地和旧回调产生非法展开。

| 情况 | 规则 |
|---|---|
| `cutscene && cutsceneKind==CUTSCENE_SHRINE` | 唯一接受此手势的过场。准备阶段、首帧等待阶段也可按。 |
| `domainCd>0` | 不可用；暂停期间冷却不下降。 |
| `domainTicks>0` | 不可重复展开。 |
| 五条死亡、`KO`、`downTicks>0`、`knockedAir`、`captured`、`scripted` 或 `hitstun>0` | 不可用；过场冻结这些状态，不等其自然恢复。 |
| 五条普通跳跃或普通动作途中 | 允许；接受后中断其当前动作，进入 `DOMAIN_CAST`。这是反制入口的明确补充，不受 `free()` 普通出招入口限制。 |
| 双方任一 `hpMilli==0`，或 `outcome!=OUTCOME_NONE` | 不可用。 |
| 已经进入对撞片 | 不再接受展开。 |

手势参数：

- 屏幕任意位置，包括黑边；系统手势区域仍由系统处理。
- 主指持续按住 **450ms**。
- 从落点累计最大位移超过 **24dp** 取消；返回原位不恢复。
- 主指抬起、`ACTION_CANCEL`、失焦、后台均取消。
- 第二根手指不接管主指、不叠加进度。
- 进入过场前已经按住的手指不算，必须产生新的 DOWN。
- 提交成功后，该次触摸直到全部抬起都被吞掉，不能落到战斗按钮上。

**末尾处理：**最后 450ms 内仍可开始。原片播完时，若已有合法长按尚未结束，保留幕布与末帧，最多等该手势剩余时间；成功则换片，松开则结束原过场。不允许片尾之后重新开始手势。

#### 提示

在屏幕底部安全区上方 24dp，使用半透明黑底，避免覆盖源片中心字幕：

- 可用：`长按屏幕 · 展开无量空处`
- 按住：`正在展开`，落点周围半径 28dp、线宽 3dp 的进度环，`elapsed/450ms`。
- 冷却：`无量空处冷却中 · XX.X秒`
- 倒地／控制中：`当前状态无法展开`
- 成功：`领域对撞`，短显后由新片接管。

冷却文字显示冻结值；进度使用前台单调时钟，不读取 `world.tick`。

#### 视频异常

- 宿傩视频加载失败、首帧超时或播放错误：不要直接吞掉反制机会。显示简洁兜底卡片 `伏魔御厨子正在展开`，保留同一手势入口 **1.00 秒**，然后按正常片尾规则结算。
- 已经成功接受反制后，对撞片出错：直接完成对撞结算，不回退成单方御厨子，也不退还已经承诺的展开。
- 后台不累计手势或兜底卡片时间；回前台重新按。
- 退出对局作废整个会话，不展开任何领域。

#### 线程与结算接入

现状的阻塞不只来自 `World.step()`：`BattleLoop` 在过场时连战斗帧回调都停掉，`Curtain.onTouchEvent()` 则直接返回 `true`。因此不能仅给 `TickInput` 增加一个按钮。

采用以下路径：

1. `Curtain` 在 UI 线程识别手势；`BattleView.setInputBlocked(true)` 继续保持。
2. 成功后向战斗线程投递新增命令 `tryCounterDomain(expectedCastId)`。
3. 战斗线程再次校验资格及 ID。成功时：
   - 清除简易领域与输入；
   - 五条进入 `Fighter.DOMAIN_CAST`，停主动移动；
   - `cutscene` 保持 `true`；
   - `cutsceneKind=CUTSCENE_CLASH`；
   - `castId++`，让宿傩旧视频回调失效；
   - 发出新 `DOMAIN_CUTSCENE` 事件。
4. 主线程收到接受结果后替换媒体，不经过旧的 `cutsceneDone()`，不中途恢复 BGM、SFX 或战斗触摸。
5. 新片结束，`endCutscene(newCastId)` 执行一次原子提交：

```text
shrineTicks = 720
shrineNext  = 60
domainTicks = 960
clashTicks  = 240
gojo.state  = FREE
cutscene   = false
清输入
refreshSureHit()
```

同时保留 `openShrine()` 中断魔虚罗的现有副作用，并各发一次 `SHRINE_OPEN`、`DOMAIN_OPEN`、`SHRINE_CLASH`。

建议抽取共用初始化方法；**不能先调用旧 `endCutscene()` 开御厨子，再调用普通 `startDomain()` 播第二轮单方视频**。也不能在两域状态未齐备时调用 `voidTakesControl()`，否则宿傩会被错误打断。

#### 沿用的战斗规则

- 反制对撞和普通后开对撞均为 `SHRINE_CLASH=240`。
- 对撞期间两域持续时间照常下降。因此没有额外中断时，2 秒后御厨子约剩 4 秒，无量空处约剩 6 秒。
- 宿傩被击倒在地或抓进瞬移连段，沿用 `endShrine(true)`；普通受击、浮空不直接判负。
- 无量空处失败：沿用 `domainCd=DOMAIN_COOLDOWN`，即 40 秒。
- 无量空处获胜：剩余持续时间结束后才进入 40 秒冷却。
- 接受手势时不额外启动冷却；通过对撞过场状态防止重复消费。
- `shrineUsed` 已在 `resolveShrineSign()` 进入原片前设为 `true`，不得重置。
- 宿傩结印已完成，不重走 `S_DOMAIN_SIGN`，不追加结印重试惩罚。
- 现有计时顺序会在设定冷却的同一 tick 再减一次；本次保持两种对撞入口一致，不单独改成不同的“精确 4800”。

#### 新增接口、字段和常量

以下均为**拟新增**，不是当前已有：

| 位置 | 名称／初值 |
|---|---|
| `World` | `CUTSCENE_CLASH=2` |
| `World` | `canCounterDomain(int expectedCastId)`、`tryCounterDomain(int expectedCastId)`，后者返回是否接受 |
| `CutscenePlayer` | `CLASH=2`，资源表增加 `domain_clash` |
| app 手势状态 | `counterPointerId=-1`、`counterDownUptimeMs=0`、`counterDownX/Y=0`、`counterPending=false` |
| app 会话状态 | `playbackGeneration=0`、`completionPending=false`、`fallbackRemainingMs=0` |
| app 常量 | `COUNTER_HOLD_MS=450`、`COUNTER_MOVE_SLOP_DP=24f`、`COUNTER_FALLBACK_MS=1000` |

450ms 属于过场交互时间，**不伪装成战斗 Tuning tick**。录制／回放记录“该 `castId` 接受反制”的外部命令，核心结果不依赖视频播放位置。

所有媒体回调、首帧通知和超时都携带 generation；仅检查共享 `mSession` 不足以隔离替换前的异步回调。仍保持最多一个活跃播放器，可在换片时释放旧实例并建立新实例，避免旧监听事件冒充新片。

`BattleActivity.cutsceneDone()` 也必须先核验当前会话，不能像现状那样先恢复音乐再交给 World 判旧 ID。

**AI 建议：本次不增加宿傩在五条视频内的反制。**用户没有要求对称机制，而且当前五条先开会打断宿傩结印；自动反制会扩大本次规则变更。

### C. 简易领域

**结论：敌方御厨子实际展开后，长按跳跃 0.25 秒开启简易领域；没有冷却、不消耗领域次数或资源。它只中和御厨子必中，普通攻击按原规则结算。自己开始领域展开的同一时刻，简易领域立即消失。**

本稿补充采用：**固定地面圆、允许圈内移动和出招、抵挡三轮御厨子后被削掉，可立即重新长按。**数值是游戏化参数，不宣称原作给过统一半径或耐久。

#### 跳跃输入仲裁

仅在“可开始简易领域”的状态下，把跳跃改为短按松手跳、长按开领域；其他场景仍按下即跳。

| 输入 | 结果 |
|---|---|
| 敌方领域内，按住不足 30 tick 后松开 | 写入原 `bufJump`，沿用 `INPUT_BUFFER=14`；地面时起跳。 |
| 连续按住达到 30 tick | 开简易领域；消耗本次跳跃意图，之后松手不再跳。 |
| 按跳跃期间点体术 | **下砸苍拳优先**；取消简易领域蓄势与待释放跳跃，沿用 `jumpHeld` 组合。 |
| 阈值同 tick 点体术 | 仍然下砸优先，不能先开简易领域再顺带出拳。 |
| 蓄势期间按闪避、苍、赫、茈、领域 | 取消本次蓄势与待跳，按原动作规则执行。 |
| 蓄势期间只推摇杆 | 可以移动；圆心取实际开成时的位置。 |
| 成功后仍不松跳跃 | 不自动刷新耐久、不在破碎后自动重开；必须松开再按。 |

`TickInput` 目前只有 `jump` 和 `jumpHeld`，没有松开边沿。新增 `jumpUp`、`jumpCancel`：

- 正常 UP 才能兑现短按跳跃。
- `ACTION_CANCEL`、后台或输入清空只取消，不误跳。
- `clearEdges()`、`clearAll()` 和 Controls 采样一起更新。
- 在 `latch()` 写入 `bufJump` **之前**完成路由，否则仍会按下就跳。

手指按下时确定本次手势模式。蓄势中敌方领域结束，则取消蓄势，但保留本次短按的松手跳语义；受击、倒地或切过场则彻底取消，不补跳。

#### “身处敌方领域内”与施放资格

当前御厨子没有空间半径判定，`updateShrine()` 直接向五条发必中攻击。因此本次沿用：

```text
enemyDomainContainsGojo = shrineTicks > 0
```

即全场、所有高度都在敌方领域内，不新增御厨子半径。

简易领域施放还要求：

- `domainTicks==0`，没有自己的领域；
- 非 `cutscene`、非固定演出、未分胜负；
- 五条存活、落地、`state==FREE`；
- 无 `hitstun`、`downTicks`、`knockedAir`、`captured`、`scripted`。

地面要求是为地面圆和跳跃输入作的最小实现补充；空中跳跃输入沿用原行为，不暗中蓄一个落地即开的简易领域。

| 状态 | 能否使用 |
|---|---|
| 无量空处冷却中 | 能；不检查 `domainCd`。 |
| 无量空处已经被击碎，御厨子仍在 | 能。 |
| 领域对撞中 | 仍算在敌方领域内，但自己的 `domainTicks>0`，不能叠开。 |
| 宿傩仅结印／正在播单方过场 | 还没有 `shrineTicks`，不能开；此时使用 B 的反制入口。 |
| `shrineBurn>0`、御厨子已经结束 | 不能，因为已不在敌方领域内。 |
| 将来增加五条术式烧断 | 不把烧断作为简易领域禁用条件。当前代码的 `shrineBurn` 属于宿傩，不能当成五条烧断。 |

#### 范围、动作与耐久

- 圆心：开启时的 `(gojo.x,0)`。
- 半径：**120 世界单位**，战场宽度 1280 的约 9.4%。
- 不跟随人物移动。
- 地面保护判定：`abs(gojo.x-simpleDomainX)<=120`。
- 圈内允许走动和出招；不套用“三轮必须原地不动”的个人限制。
- 普通攻击不会因为简易领域而失效：无限、展延、无敌、特殊穿透继续按现有系统判定。
- 普通受击不直接清空圈；受击导致离地、倒地或离开圆时才结束。
- 主动跳跃立即离开地面保护范围；瞬移按移动后位置立即判定，出圈即结束。
- 不增加每秒资源消耗、结束后硬直或隐藏冷却。

耐久按**实际发出的御厨子轮次**消耗：

1. 初始 `simpleDomainRounds=3`。
2. 每轮必中来临，若简易领域有效：该轮不伤血、不击退、不加硬直，耐久减 1。
3. 第三轮仍完整挡住，随后圆被削掉。
4. 宿傩硬直导致轮次作废时不削耐久。
5. 不根据“是否最终扣血”判断削弱；有效圈先承担本轮必中。
6. 破碎后立刻允许新的 DOWN；仍需完成正常的 30 tick 展开动作，没有额外等待。

**30 tick 是每次发动动作，不是重开冷却。**破碎发生在当前斩击之后，下一轮还有 60 tick，玩家及时重开可以继续保护；不人为制造必吃伤害窗口。

#### 必中接入与顺序

`refreshSureHit()` 改为：

```text
宿傩对五条必中 =
    shrineTicks > 0
    && clashTicks == 0
    && !simpleDomainProtectsGojo()
```

但**仅改这个布尔值还不够**。当前 `Defense.resolve()` 在目标没有无限时仍可能返回全部伤害，因此应在 `updateShrine()` 的斩击分支中明确处理：

```text
宿傩本轮作废 → 原 kind=2
否则简易领域有效 → 消耗一层，跳过 apply(attack)
否则 → 原来的必中攻击结算
```

简易领域挡住时，`SHRINE_SLASH` 新增 `kind=3`，不伪装成无限挡下，也不增加 `shrineDealt`。

顺序明确为：

1. 输入仲裁；满 30 tick 时开圈。
2. 正常动作、攻击结算。
3. 在御厨子结算前校验圆是否仍有效。
4. 处理御厨子轮次。
5. 位移积分后再次检查出圈／离地，供下一 tick 使用。

与现有 `updateShrine()` 在 `integrate()` 前的顺序一致；瞬移等直接修改位置的路径必须在本轮斩击前检查。

#### 结束条件与状态

以下情况立即清除，原因仅用于表现：

| 原因 | 时刻 |
|---|---|
| 自己领域展开 | `startDomain()` 或反制接受入口的最开始，先清圈再进过场。 |
| 敌方领域结束／崩解 | `endShrine()` 内。 |
| 三轮耐久耗尽 | 第三轮中和完成后。 |
| 出圈、主动跳跃、被打离地、倒地、被抓住 | 状态成立后立即。 |
| 死亡、胜负确定、重置对局 | 统一清理。 |

开启失败的领域按键不清圈；必须是**真正接受了自己的领域展开**才清除。自己的过场结束或领域破碎后也不自动恢复旧圈，要重新长按。

新增核心状态、参数与事件：

| 类别 | 名称与取值 |
|---|---|
| `Tuning` | `SIMPLE_DOMAIN_HOLD=30` |
| `Tuning` | `SIMPLE_DOMAIN_RADIUS=120f` |
| `Tuning` | `SIMPLE_DOMAIN_ROUNDS=3` |
| World 状态 | `simpleDomainRounds=0`，大于 0 表示开启 |
| World 状态 | `simpleDomainX=0f`、`simpleDomainHoldTicks=0` |
| 输入状态 | `jumpSimplePending=false`、`jumpGestureConsumed=false` |
| 新方法 | `canStartSimpleDomain()`、`simpleDomainProtectsGojo()`、`openSimpleDomain()`、`closeSimpleDomain(int reason)` |
| `Events` 类型 | `SIMPLE_DOMAIN=35` |
| 事件 value | `SIMPLE_OPEN=1`、`SIMPLE_ERODE=2`、`SIMPLE_CLOSE=3` |
| OPEN／ERODE 的 kind | 剩余层数 3、2、1、0 |
| CLOSE 的 kind | `OWN_DOMAIN=1`、`ENEMY_END=2`、`ERODED=3`、`LEFT_AREA=4`、`DISABLED=5`、`FIGHT_END=6` |
| 既有 SHRINE 事件扩展 | `SHRINE_SLASH.kind=3`：简易领域中和 |

不新增 `simpleDomainCd`。

#### 画面与音效

画面：

- 开圈：12 tick 从半径 0 展至 120；逻辑保护从开成瞬间生效，不等待视觉展开。
- 地面投影为椭圆，横半径 120、纵半径 24；淡米白线配浅蓝内缘。
- 三段小刻线表示耐久，不放第二条大血条。
- “简易领域”在角色上方显示 42 tick；跳跃按钮蓄势时画进度环。
- 被削一轮：边缘向内收缩 4px 后恢复，少一段刻线。
- 耗尽：圆线分成 12 段向外散开，18 tick 消失；避免复用无量空处大结界碎裂特效。
- 自己展开领域时只快速收光，不播放“被打破”。

新音效参照音效文档开头的**实际落地基准**：普通命中最强 80ms RMS 约 −13dBFS、峰值≤−1dBFS；以下增益相对普通命中。48kHz 单声道、离线合成，运行时由现有 `SfxDirector` 分派。

| 音效 | 配方 | 时长／增益 |
|---|---|---|
| `simple_open` | 220Hz 正弦 + 440/660Hz 弱泛音，15ms 起音；900→500Hz 窄带气流收拢，末尾轻清鸣 | 240ms／−7dB |
| `simple_erode` | 1.2–3kHz 带通噪声 8ms 瞬态，叠 680/940Hz 非整数双音快速衰减；不加爆炸低频 | 100ms／−9dB |
| `simple_break` | 三个相隔 18ms 的干裂脉冲，叠 700→350Hz 下扫；短气流散去 | 220ms／−5dB |

正常收圈复用已有消散类音色，不新增循环声。

- `SHRINE_SLASH.kind=3` 保留很轻的切口声，`simple_erode` 为主声；不播受击和无限音。
- 最后一层只播 `simple_break`，不叠一次 erode。
- 过场期间仍全部停止战斗 SFX；分镜撞击声烘焙在视频内。

#### AI 与平衡

**首版沿用现有 AI，不新增读输入、强制破圈或加速斩击。**宿傩现有展延体术、世界斩等仍能形成压力；简易领域不会替五条挡住这些手动攻击。

御厨子全吃约 330–400 血的现状会明显改变：熟练玩家可以反复展开，理论上把必中伤害降到零。这是“没有冷却、没有自己的领域也能用”的合理结果，不能暗中抬高御厨子伤害补回来。

平衡代价已经存在：需要落地、管理固定圆、重复长按，并处理宿傩普通攻势。三轮削弱体现强领域持续剥离防护；不再额外叠资源、僵直或重开锁。

#### 导演与音频断言

- 新 `SIMPLE_DOMAIN` 事件每次只消费一次，关闭原因不被当作耐久数。
