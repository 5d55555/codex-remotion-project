# Astra 设计稿 第一轮：架构、安装、登录、界面、沙箱、性能、测试

# Android 本地 Codex 客户端设计稿 v0.1

本轮建议确定：**纯 Java 原生界面、minSdk 26、targetSdk 28、arm64 优先、固定 Codex 0.166.0、前台服务管理本地 app-server、项目放应用私有目录。**

最大的产品边界是：**这是运行在 Android 应用沙箱里的本地 Agent，目前不能声称每个项目都有独立沙箱。** 代码和命令在手机执行，模型请求仍然需要联网，相关提示词与文件内容可能发送给模型服务。

以下以你提供的实测、仓库结构和本地 0.166.0 Schema 为实现基线；在线文档只用于补充边界，不用新版文档覆盖已验证协议。没有修改任何文件。

## A. 总体架构

**结论：首版采用一个 Android 应用进程、一个前台服务、一个共享 app-server；全局同时只执行一个用户 turn。**

### SDK、ABI 与发行方式

| 项目 | 具体选择 | 理由 |
|---|---|---|
| minSdk | 26 | 与参考项目一致，减少低版本兼容成本 |
| compileSdk | 36 | 沿用现有构建环境 |
| targetSdk | 28 | 满足下载后二进制从私有目录执行的首版目标 |
| 正式 ABI | arm64-v8a | 主流手机；不支持 32 位系统 |
| 测试 ABI | x86_64 | Linux 集成测试与模拟器验证 |
| 分发 | 自用侧载 APK | 不以应用商店发行要求作为首版目标 |
| Java | core Java 17；Android 沿用仓库工具链 | Android 端调用仍须符合 API 26，不能把 JVM 版本等同于系统 API 可用性 |

Android 官方明确：target ≥29 时不能直接执行可写应用主目录内的文件。Android 15 的最低安装 target 是 24，因此 target 28 至少不触犯这一条限制；这不等于保证所有 Android 16 或厂商设备都能正常运行。[Android 10 行为变更](https://developer.android.com/about/versions/10/behavior-changes-10)、[Android 15 行为变更](https://developer.android.com/about/versions/15/behavior-changes-all)

**target 28 是待真机验证的工程选择，不是长期兼容承诺。** 下一轮根据 Luna 结果决定是否保留。

### 进程与生命周期

```text
Activity / Fragment
        │ 绑定、观察状态
        ▼
RuntimeService（前台服务，同一应用进程）
        ├── RuntimeSupervisor
        ├── LoopbackProxy
        ├── 安装 / 登录任务
        └── codex app-server
                ├── codex-code-mode-host
                └── shell / 工具子进程
```

- Activity 不直接持有 `Process`、流或代理。
- `RuntimeService` 是唯一运行时所有者，防止旋转、重复点击导致多实例。
- 登录期间运行独立 `codex login --device-auth`，暂停 app-server，避免凭据竞争。
- 多会话共享 app-server，用 `threadId` 分流。
- 首版全局仅一个用户 turn 在运行；其他会话允许查看、编辑草稿，不自动排队执行。
- 不主动启用多 Agent 并发；确有子 Agent 时也不能假定全局单 turn 意味着只有一个工具进程。

前台服务由用户在可见界面触发，进入服务后立即发布通知。采用标准的 `startForegroundService → startForeground` 流程。[Android 前台服务启动说明](https://developer.android.com/develop/background-work/services/fgs/launch)

| 状态 | 前台服务 | 唤醒锁 |
|---|---|---|
| 下载、校验、安装 | 保持 | 活跃工作期间 |
| 等待浏览器登录 | 保持 | 不持续持有 |
| Agent 工作 | 保持 | 持有 |
| 等待审批/用户输入 | 保持 | 释放 |
| 无任务且界面退后台 | 最多保留 60 秒，随后关闭运行时 | 无 |

唤醒锁使用 `PARTIAL_WAKE_LOCK`，每次超时 10 分钟，每 5 分钟仅在确有活跃工作时续期；任务结束、错误和取消都在 `finally` 释放。不持有 Wi-Fi 锁，不保持屏幕常亮。

通知频道：

- `runtime`：低重要性，显示“正在修改 project-a · 02:13”，操作“打开”“停止”。
- `attention`：默认重要性，用于审批和需要登录。
- `downloads`：低重要性，显示进度、暂停、取消。
- 锁屏默认隐藏命令、文件名和登录代码。

### 崩溃与重启

- 服务使用 `START_NOT_STICKY`；首版不做开机自启。
- app-server 意外退出：允许重建连接，退避 1、3、10 秒，10 分钟内最多 3 次。
- **重启进程不等于重发任务。** 已发送但未确认的 `turn/start` 必须先读取历史，禁止自动重放。
- 未完成任务标记“运行中断，文件可能已修改”，提供“查看改动”“继续”。
- 网络断开但子进程仍存活：让 Codex 自己重试，不能因几秒没有 token 就杀进程。
- 正常停止先 `turn/interrupt`，等 5 秒，再终止运行时。
- 完整清理子孙进程需要验证进程组方案；Java `Process.destroy()` 不能被当作清理整个进程树的保证。

### 模块

沿用 `android-shinjuku` 的 `core / app / smoke` 结构：

| 模块 | 职责 |
|---|---|
| `core`，纯 Java | 安装状态机、下载续传规则、SHA-512、tar 筛选、登录输出解析、JSON-RPC 编解码、事件归并、会话状态、审批映射、路径规则、重试策略 |
| `app` | Activity/Fragment、Service、Android 网络与证书、进程启动、SQLite、SAF、通知、唤醒锁 |
| `smoke` | Robolectric；与 Paparazzi 隔离 |
| core 集成测试源集 | 真实 x64 Codex、协议回放、chroot 测试 |

核心接口建议：`ProcessRunner`、`Clock`、`FileStore`、`HttpTransport`、`EventStore`、`RuntimeObserver`。避免 core 依赖 `android.*`。

### 本地代理

建议保留你的 Java CONNECT 方案，并加以下约束：

- 绑定 `127.0.0.1:0`，由系统分配端口。
- 每次运行生成 128-bit 随机代理口令；URL 使用代理认证，日志必须脱敏。
- 不能把 localhost 当作应用身份隔离：其他应用也可能尝试连接。
- 首版支持 HTTPS CONNECT、WebSocket 隧道；同时明确实现普通 HTTP 正向代理，否则不能宣称 `HTTP_PROXY` 可用于任意 HTTP 工具。
- 不做 TLS 解密，TLS 由 Codex 与目标服务端建立。
- 请求头上限 16 KiB、头部超时 10 秒、上游连接超时 15 秒。
- 最大 16 条并发隧道；使用有界线程池或 NIO，禁止无界创建线程。
- 隧道双向转发支持 half-close；不要用 30 秒读取超时误杀长连接。
- Android DNS 在后台线程解析；网络切换关闭失效连接，由 Codex 重建请求。
- 网络模式默认“跟随系统”，可选“直连”“手动 HTTP 代理”。手动代理覆盖系统设置。
- PAC、认证代理无法处理时明确报错，不能偷偷切直连。
- 上游解析必须避免把请求再次送回自身代理形成循环。

证书导出：

1. 从 `AndroidCAStore` 读取证书，按 DER SHA-256 去重。
2. **系统 CA 默认启用；用户安装 CA 默认关闭，设置里显式开启。**
3. 同一信任选项同步应用于 Java 下载器和 Codex，避免两套信任策略。
4. 写 `ca.pem.tmp`，同步后原子替换。
5. 每次启动检查证书集合指纹；变更后在空闲时重启运行时。
6. 不关闭证书校验，不把任何服务端证书自动加入信任。

这比默认无提示导出全部用户 CA 更适合持有登录凭据的应用。

### 环境变量

通过明确白名单构造子进程环境，不继承任意开发机或应用环境：

| 变量 | 值 |
|---|---|
| `HOME` | `R/home` |
| `CODEX_HOME` | `R/codex-home` |
| `TMPDIR`、`TMP`、`TEMP` | `R/tmp` |
| `PATH` | `R/shim/bin:R/tools/bin:<当前版本>/bin:/system/bin` |
| `SHELL` | `/system/bin/sh`；仅作补充，不依赖它选 shell |
| `SSL_CERT_FILE` | `R/certs/ca.pem` |
| `CODEX_CA_CERTIFICATE` | 同上，0.166.0 验证后一起设置 |
| `HTTP_PROXY`、`HTTPS_PROXY` | `http://<用户>:<随机口令>@127.0.0.1:<port>` |
| `http_proxy`、`https_proxy` | 与大写一致 |
| `NO_PROXY`、`no_proxy` | `localhost,127.0.0.1,::1` |
| `ALL_PROXY`、`all_proxy` | 删除，避免不同工具解释冲突 |
| `LANG`、`LC_ALL` | `C.UTF-8`，在真机验证中文路径 |
| `TERM` | `dumb` |
| `NO_COLOR` | `1` |
| `TZ` | Android 当前时区 ID |
| `ANDROID_ROOT` | `/system` |
| `ANDROID_DATA` | `/data` |

必要 Android 系统工具变量从系统环境白名单保留，不能随意继承 `LD_PRELOAD`、`LD_LIBRARY_PATH`、`BASH_ENV`、`ENV`、`OPENAI_API_KEY`。

`bash` 链接只是选壳兼容方案，**不能称为安装了 Bash**。给 Agent 的开发指令明确说明：当前是 Android mksh，优先 POSIX shell；不保证 Python、Node、Git、编译器存在。

官方文档说明自定义 CA 配置适用于登录、HTTPS 与安全 WebSocket；具体变量优先级仍以固定版测试为准。[Codex 登录与 CA 配置](https://learn.chatgpt.com/docs/auth)

### `config.toml`

首版最小配置：

```toml
cli_auth_credentials_store = "file"
sandbox_mode = "danger-full-access"
approval_policy = "untrusted"

[features]
code_mode_host = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false
```

这里的 `all` 仅继承我们已经清理过的子进程环境。不要把 API Key 作为长期环境变量传入 app-server。

模型、effort 不写死；从 `model/list` 选择。创建和恢复 thread 时显式传 `sandbox`、`approvalPolicy`、`approvalsReviewer:"user"`、绝对 `cwd`，防止依赖旧会话默认值。配置字段在发布前用 0.166.0 做一次解析验证。[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

## B. 安装 Codex CLI

**结论：下载完整压缩包并验证，再仅解出两个运行文件；首次安装最低要求 768 MiB 可用空间。**

### 版本与来源

- 默认“已测试版本 0.166.0”。
- APK 内置版本清单：版本、ABI、tar 路径、完整 SRI SHA-512、压缩大小、两个文件的尺寸与路径。
- 不在文档里臆造摘要；发布时从官方源取得并固化。
- 默认“自动”：官方 npm → npmmirror。
- 设置提供“仅官方”“仅国内镜像”“自动”。
- 国内镜像只改变下载位置，**不能改变预期摘要**。
- 已确认 npmmirror 服务存在；这个具体大包是否完整、支持续传，仍需下一轮验证。[npmmirror registry](https://registry.npmmirror.com/)
- 自定义镜像首版不开放，减少错误与不可复现问题。

### 续传规则

保存 `.part` 和元数据：URL、版本、ABI、ETag、Last-Modified、总长度、已下载长度。

- 请求 `Accept-Encoding: identity`。
- 续传使用 `Range: bytes=N-`，可用时附 `If-Range`。
- 206 必须校验 `Content-Range` 起点等于 N。
- 返回 200：丢弃旧片段，重新开始。
- 416：仅在本地长度等于预期长度时进入全包校验，否则重下。
- 源切换默认重新下载，不拼接不同服务器的未验证片段。
- 网络错误重试 1、3、10 秒；之后显示“重试 / 切换下载源”。
- 无网进入等待网络；不不断刷失败通知。
- SHA-512 始终覆盖完整 tar.gz，不能只校验续传部分。

### 提取与原子切换

1. 下载完成并验证全包 SHA-512。
2. 遍历 tar，只接受清单中两个精确路径的普通文件。
3. 拒绝绝对路径、`..`、硬链接、符号链接、重复目标和超出上限的尺寸。
4. 写入同文件系统 staging 目录，设置权限并同步。
5. 检查 ELF 架构、`codex --version`、app-server 初始化。
6. staging 重命名为正式版本目录。
7. 原子替换 `active.json`。
8. 保留一个旧版本，成功运行后按设置清理。

不安装包内 glibc `rg`、voice 或 bwrap。**Android 可用的 `rg` 是独立工具包任务**，须使用验证过的 Android/静态构建；缺失时界面列为能力缺失，不能把它伪装成已有。

升级不能覆盖正在执行的二进制。等待 turn 结束后切换；下载和校验可提前进行。

### 空间与进度

预检公式：

```text
所需新增空间 =
尚需下载的压缩字节
+ staging 解压字节
+ 128 MiB 保留量
+ 必要迁移备份空间
```

首次安装最低门槛 768 MiB。升级时旧版本继续占用磁盘，但不要重复算成“新增空间”。每写入约 16 MiB 再检查剩余空间。

安装界面分阶段，不造一个不准确的总百分比：

- 下载：`82 / 164 MB · 3.2 MB/s · 约 26 秒`
- 校验：已校验字节比例
- 安装：两个文件的解压进度
- 启动检查：不确定进度条

速度用近 5 秒平滑平均，500 ms 更新；数据不足时不显示 ETA。

失败文案：

| 情况 | 文案 |
|---|---|
| 空间不足 | “可用空间不足。还需要约 420 MB，可清理旧版本后重试。” |
| 网络中断 | “下载已暂停，已下载内容会保留。” |
| 摘要不符 | “安装包校验失败，未安装。请重新下载或切换来源。” |
| 无法执行 | “当前设备无法启动 Codex。请查看兼容性诊断。” |
| 升级失败 | “新版本启动失败，已保留原版本。” |

“升级到最新”属于实验入口：显示协议未验证提示，下载前展示版本和体积；必须通过初始化与协议自检，不自动迁移默认版本。运行过新版本后的历史数据未必能被旧版读取，因此二进制回退和数据回退要分开设计。

## C. 登录

**结论：严格按要求用 CLI 设备码登录；成功由进程结果与账号状态共同判断，不能靠一句输出或 `auth.json` 存在判定。**

### 实现与状态机

```text
未登录 → 启动登录 → 获取设备码 → 等待授权
                              ├→ 验证账号 → 已登录
                              ├→ 已过期 → 自动重新获取
                              ├→ 网络异常 → 等待/重试
                              └→ 需开启设备码 / 其他失败
```

- `ProcessBuilder` 参数数组启动，禁止拼 shell 命令。
- `redirectErrorStream(true)`，stdout/stderr 重定向到独立 attempt 日志文件。
- 文件放私有目录，0600；解析器维护字节偏移，每 250 ms 读取新增内容。
- 使用增量 UTF-8 解码器，正确处理字符与 ANSI 序列跨块。
- 解析时去除 CSI/OSC、处理 `\r`；保留受限原始日志用于诊断。
- URL 只接受 HTTPS 且 host 为 `auth.openai.com`；代码从指定上下文提取，不能随便拿日志中的八位字符串。
- 单次日志上限 2 MiB，超限中止并提示异常；成功后删除设备码日志。
- 每个尝试带 generation ID，旧进程输出和旧倒计时不能覆盖新代码。

### 过期与自动刷新

- 解析 “expires in 15 minutes”；缺失时固定版可按 15 分钟显示**预计**有效期。
- 使用 `elapsedRealtime()`，避免修改系统时间影响倒计时。
- 终端输出过期、进程退出等证据优先于估算倒计时。
- 倒计时到零先标记不可使用，检查进程状态与新凭据，避免授权成功与刷新竞争。
- 确认未成功后停止旧登录进程，最多等 3 秒，再启动下一次；不允许两个登录进程并存。
- 登录页可见时持续自动刷新。
- 跳到浏览器后允许后台续期，但无人回到应用连续 30 分钟后暂停，通知“登录已暂停，点此获取新代码”。
- 网络错误按 2、5、15、30 秒退避，恢复网络后再尝试；设备码禁用不自动循环重试。

### 结果判断

| 证据 | 处理 |
|---|---|
| CLI 退出 0，且 `account/read` 返回有效账号 | 登录成功 |
| CLI 退出 0，但离线无法验证 | “授权已保存，联网后验证”，不重新索取代码 |
| 只有旧 `auth.json` | 不能证明本次成功 |
| 明确过期信息 | 自动换码 |
| 明确设备码禁用信息 | 显示开启指引 |
| DNS、代理、TLS 错误 | 网络问题卡片，保留可用代码 |
| 非零退出且无法分类 | “登录未完成”，提供脱敏详情和重试 |

官方要求个人账户在 ChatGPT 安全设置开启设备码登录，工作区则可能需要管理员开启。[设备码登录说明](https://learn.chatgpt.com/docs/auth)

### 页面

纵向顺序：

1. 标题“连接你的 Codex”。
2. 说明“登录后，Agent 将在这台手机上处理项目文件”。
3. 代码卡片：32sp 等宽字体，按组显示，支持选择。
4. 主按钮“复制代码并打开浏览器”，旁边独立“复制”。
5. 倒计时环＋`14:32 后过期`；必须有文字，不能只用颜色或圆环。
6. 辅助文本“过期后会自动获取新代码”。
7. “登录遇到问题”。
8. 次级入口“改用 API Key 登录”。

API Key 用密码输入框，调用固定版支持的 `codex login --with-api-key`，通过 stdin 写入后关闭；不放 argv、不写日志。显示“API 使用独立计费”，不暗示套餐额度通用。

成功后显示账号和套餐 600 ms，再进入工作区选择；尊重系统减少动画设置。账号验证失败不先播放成功动画。

## D. 主界面与交互

**结论：三个底部入口“会话 / 文件 / 设置”，对话是会话内部页面；聊天时收起底部导航，把操作区留给输入框。**

### 信息结构

- **会话**：当前工作区切换、最近会话、搜索、新建。
- **对话**：顶部返回、会话标题、运行状态、更多菜单；底部输入。
- **文件**：当前工作区目录树、搜索、改动列表。
- **设置**：账号、Codex 版本、网络与证书、运行模式、存储、后台运行、诊断。

会话列表底部放“新对话”，不把唯一的新建入口放在右上角。对话顶部的工作区名称可点开文件页；底部提供返回最新消息浮动按钮。

### 对话事件展示

| 类型 | 展示方式 |
|---|---|
| `userMessage` | 轻底色气泡，支持复制与重新编辑 |
| `agentMessage/commentary` | 时间线式状态文本，14sp，视觉弱于正式回答；完成后可折叠为执行过程 |
| `agentMessage/final_answer` | 正文 16sp Markdown，不用厚重气泡包裹 |
| `reasoning` | “推理摘要”折叠项；只展示协议提供的摘要，不虚构或承诺完整内部思考 |
| `commandExecution` | 命令、cwd、状态、耗时；输出默认折叠，仅运行时显示最近 8 行 |
| `fileChange` | 文件数、增删统计、状态；点开统一 diff，新增/删除同时用符号与颜色 |
| `turn/diff/updated` | “本轮改动”入口，更新同一份汇总，不反复追加卡片 |
| `turn/plan/updated` | 顶部紧凑进度“2/5 已完成”；展开显示步骤 |
| token/额度 | 默认不打断对话；顶部状态弹层展示 token 与额度重置时间 |
| `warning` | 黄色行内卡片，可展开详情 |
| `error` + `willRetry` | “正在重试”或“本轮失败”；不能一律红色失败 |
| 未知 item | “此版本暂不支持的事件”，保留诊断类型，避免崩溃 |

`item/completed` 的完整内容替换对应 item 的临时累积内容，不能在 delta 后再次追加一遍。

命令退出码 `null` 不能显示成成功；运行耗时优先使用服务端字段，否则按单调时钟估算。

### 输入与模型

- 输入框 1–6 行，超过后内部滚动。
- 手机 Enter 换行，发送用按钮；物理键盘 Ctrl+Enter 发送。
- 空闲：主按钮“发送”。
- 运行：保留明确“停止”按钮；输入内容后出现“追加指令”。
- 追加调用 `turn/steer`，携带 `expectedTurnId`。
- 如果 turn 已结束导致 steer 失败，保留草稿，提示“本轮已结束，点发送开始下一轮”，不自动发送新任务。
- 模型从 `model/list` 的非隐藏项构建；默认使用服务端默认模型。
- effort 从对应模型支持列表构建，默认服务端默认值；不用固定枚举假设所有模型支持 `high`。
- 模型/effort 修改在下一轮生效，运行期间明确显示这一点。
- 非幂等请求发送前持久化本地消息 UUID；超时后先对账，不能立即重发。

### 审批和用户提问

使用底部 sheet，包含命令/文件、cwd、理由、权限范围；长内容可打开全屏。后台只发通知，不弹 Activity。

按钮：

- “允许这一次” → `accept`
- “拒绝此次操作” → `decline`
- 更多：“拒绝并停止本轮” → `cancel`
- 会话授权 → `acceptForSession`

**不能统一标为“本会话都允许”。** 本地 Schema 明确：

- 命令：适用于对应 session-scoped approval cache。
- 文件：适用于同一批文件的后续更改。

文案分别为“本会话记住此命令授权”“本会话允许这些文件的后续修改”，并按请求实际提供的可选决策展示。

`item/tool/requestUserInput` 按 question ID 收集答案，以 `{answers:{id:{answers:[...]}}}` 回复。关闭 sheet 不等于提交默认答案；保留“等待回答”卡片。

服务端请求必须精确回复原 ID，重复请求不重复弹窗。未知请求返回协议错误并提示不兼容，不能静默接受，也不能永远挂起。

### 工作区与文件

默认创建 `workspaces/<uuid>`，显示名与目录 ID 分离。

首版共享存储采用：

1. SAF 选择目录并保存 URI 授权。
2. 导入私有工作区。
3. Agent 修改本地副本。
4. 用户“导出改动”时同步回去。

**SAF URI 不是 POSIX 路径，不能直接传给 `cwd`。** 首版不请求广泛存储权限，不提供伪装成实时挂载的功能。

导出保存基线哈希：外部文件已被其他应用修改时显示冲突，不直接覆盖。删除操作单独列出确认。

文件页：

- 目录浏览、名称搜索、文本预览、复制路径、分享、导出。
- 默认隐藏 dotfiles，可切换。
- 文本超过 1 MiB 使用分段查看。
- 二进制显示类型、大小和分享入口。
- 通过受限 `FileProvider` 分享 `content://`，默认临时只读授权。
- “用其他应用编辑”首版通过导出副本完成；不暗示编辑结果自动回写。
- 不把 runtime、凭据、日志目录暴露给 FileProvider。
- 对文件浏览、分享、导出做 canonical path 与符号链接检查。

## E. “沙箱”策略

**结论：首版只能承诺 Android 应用级隔离；默认采用“谨慎执行”，不发布不能兑现的“严格只读”模式。**

### 能力边界

Android 应用 UID 与 SELinux 提供应用级约束，但：

- 同 UID 的工具可能访问应用内部其他项目、配置、凭据和数据库。
- `cwd` 只是默认目录。
- 0700/0600 不能隔离同 UID 进程。
- Agent 具备应用已有的网络能力。
- SAF 授权不会自动变成 CLI 可用路径，但应用提供的桥接功能仍须控制范围。
- 无法把 `danger-full-access` 改个名字就称为项目沙箱。

首次启用本地执行展示一次简短说明：

> 文件和命令在本机运行，受 Android 应用沙箱限制。Agent 可能访问本应用内的其他文件；项目目录不是独立隔离区。模型请求需要联网。

设置详情进一步说明凭据与工具同 UID 的限制。

### 模式映射

| UI 模式 | `sandbox` | `approvalPolicy` | 首版状态 |
|---|---|---|---|
| 严格只读 | `read-only` | `never` | 仅内核沙箱能力探测与越界写测试通过后开放；当前预计不可用 |
| 谨慎执行，默认 | `danger-full-access` | `untrusted` | 必须验证危险命令会触发审批后开放 |
| 完全自动 | `danger-full-access` | `never` | 用户显式选择 |

默认再传 `approvalsReviewer:"user"`。

“谨慎执行”说明为：

> Codex 会对部分操作请求确认；不是每条命令都会弹窗，也不提供项目级文件隔离。

不要命名为“所有修改都需要审批”。尤其要测试 shell 重定向、脚本、`apply_patch`、code-mode-host 是否绕过预期审批。

如果 `untrusted + danger-full-access` 实测不能提供预期审批，**停止发布这档模式**。可以先发布明确标注的完全自动实验版，不能用 UI 假审批补洞。

严格只读不可用时，不自动降级为全权限；提供文件浏览功能即可。真正三档硬隔离需要独立执行 UID、受控文件代理或修改 Codex 工具执行架构，是后续独立项目。

## F. 性能

**结论：UI 只持有可见窗口和增量状态，协议流持续消费，长输出落盘；不把整个会话重绘成一个 TextView。**

### 列表与协议

- `RecyclerView`，稳定 item ID，按 `(threadId, turnId, itemId)` 索引。
- 单线程事件归并；UI 使用 payload 局部更新。
- 普通文本最多 10 Hz 刷新，Markdown 最多 4 Hz，命令输出最多 5 Hz。
- 完成、错误、审批立即刷新，不受节流延迟。
- 用户距底部 80dp 内才自动滚动；正在选字或查看历史时禁止抢滚动。
- 每页 50 个 item；优先使用你这版 Schema 已有的 `thread/turns/list`、`thread/items/list`，不要假设 `thread/read` 返回全部 turns。
- `thread/resume` 可用 `excludeTurns:true`，随后分页载入。
- stdout 协议读取、stderr 排水、磁盘写入、UI 渲染分别执行。
- JSON 行读取必须有上限，建议 32 MiB；超限明确协议错误，不能无限扩容。
- 事件队列超过 8 MiB 进入受控故障处理；不能静默丢掉完成事件或审批请求。

### 长输出

- 卡片内保留尾部 32 KiB。
- 展开页虚拟化读取，单次加载约 64 KiB。
- 每命令本地输出留存上限默认 10 MiB，超过后继续消费但标记“较早输出未保存”。
- 所有输出缓存默认上限 200 MiB，按最旧非活跃记录清理；不删除项目文件。
- 不能仅截断 delta：最终 `aggregatedOutput` 也必须走同一套限制。
- Codex 自己的日志与历史可能额外占空间，需要单独统计；UI 缓存上限不是全应用磁盘上限。

### Markdown

采用 **Markwon 4.6.2 作为固定候选版本**，经过构建验证后锁定依赖。它使用原生 Spannable 渲染，不需要 WebView。[Markwon 项目](https://github.com/noties/Markwon)

- 开启基础 Markdown、表格、任务列表、删除线。
- 首版不自动加载远程图片、不渲染任意 HTML。
- 链接只允许经过处理的 http/https，其他 scheme 不自动启动。
- 分块缓存已完成段落，流式阶段主要重算末尾块。
- 超长代码块独立文件查看器打开，避免巨型 Span。
- >64 KiB 的流式消息减少格式化，完成后分块渲染。

### 启动与内存

- App 冷启动先显示本地列表，不等待 Codex。
- 已登录用户进入会话页后预热运行时；安装/未登录时不启动 app-server。
- 空闲退后台 60 秒关闭；不以永久驻留换启动速度。
- 不启用 `largeHeap`。
- Java 堆目标 ≤96 MiB，Markdown 缓存 8 MiB，文本状态缓存 8 MiB。
- Codex 的 350 MB 文件大小不是运行时 RSS；分别测 Java、app-server、code-mode-host 的 PSS。
- 低内存回调先清渲染缓存与历史页；活跃任务内存风险必须由真机数据决定。

体验目标：中档设备本地会话列表 1 秒内可交互；运行时超 3 秒显示“正在启动”，20 秒仍未初始化显示诊断入口，而非一直转圈。

## G. 兼容性

**结论：核心支持范围先定为 Android 8–16、64 位设备；安装成功、能执行、后台存活分别验证。**

- SDK 验证点：26、28、29、31、33、34、35、36。
- 必测 arm64 4 KiB 与 16 KiB 页设备；所有自带 native 工具都检查，不能只检查 Codex。
- Android 13+ 通知权限按 target 28 的系统行为处理，不能假定可使用与 target 33 相同的请求时机。
- 拒绝通知时显示“后台任务提示不可见”的行内状态，但不要无故阻止前台使用。
- 厂商省电设置只在设置页和实际中断后提供指引；不启动就连弹权限。
- 不承诺前台服务能防止强停、内存回收或幽灵进程清理。
- 深色模式默认跟随系统，可手动浅色/深色。
- 字体缩放测试 100%、130%、200%；正文与按钮不固定高度。
- <600dp 单栏；≥600dp 会话列表与对话双栏；≥840dp 可增加可折叠文件面板。
- 横屏、分屏、旋转只重建界面，不重启运行时。
- TalkBack 为按钮、进度、退出码提供文本；流式 token 不逐字播报，只播报完成和待处理事件。
- diff 不能只靠红绿，必须保留 `+ / -` 与文字状态。
- 遵循减少动画；代码长行允许横向滚动，普通文本换行。

## H. 测试方案

**结论：JVM 验证协议与状态机，真实 Codex 验证执行闭环，Robolectric/Paparazzi 验证 Android 页面；安全与后台能力必须真机验收。**

### JVM 确定性测试

- 设备码输出分块、ANSI/OSC、中文 UTF-8、`\r`、错误代码匹配。
- 时间跳变、过期与成功竞争、旧 attempt 迟到输出。
- Range 206/200/416、源切换、摘要不符、磁盘不足。
- tar 路径穿越、重复 entry、超大尺寸、链接攻击、损坏 gzip。
- 安装各阶段断电/进程退出后的恢复。
- JSON-RPC ID、响应与通知交错、未知字段、未知请求。
- delta 与 completed 去重、重连对账、turn 状态恢复。
- 审批作用域和 user-input 精确映射。
- 100,000 个事件回放、10 MiB 命令输出，确认内存有界。
- 导出冲突、符号链接越界、撤销 SAF 授权后的状态。

### 真实 x64 Codex 集成

每次固定 0.166.0，使用隔离的临时 CODEX_HOME：

1. 初始化、账号、模型列表。
2. 创建/恢复 thread，创建文件并执行命令。
3. 对照磁盘内容校验 fileChange/diff。
4. 流式输出、非零退出、停止、steer 竞争。
5. 进程退出后恢复，确认不重复执行任务。
6. 所有审批模式组合，重点测试直接写文件、shell 重定向、脚本写文件。
7. helper 缺失、不可执行、版本不匹配。
8. 代理认证、DNS、TLS、WebSocket、半关闭与网络中断。
9. 历史分页、未知事件与大事件。
10. 新版升级与旧版数据兼容。

chroot 保留你的 Android 文件系统模拟，增加 HOME/profile 对 `bash -lc` 的影响、中文路径、无 Git/rg、临时目录不足。

**chroot 不复现 Android SELinux、应用 seccomp 或厂商进程管理。**

### Robolectric

- 冷启动与安装恢复。
- 登录→浏览器→返回、旋转、服务重新绑定。
- 生命周期变化不产生第二个 CLI。
- 通知操作、审批待处理、用户拒绝权限。
- 离线历史可读、草稿恢复、退出登录。
- SAF 导入/导出逻辑用替身测试，实际 provider 行为留给设备测试。

### Paparazzi

浅/深色 × 360dp/412dp/平板，覆盖：

- 安装下载、校验、失败。
- 登录正常、过期、网络错误、设备码禁用。
- 空会话、流式回答、命令错误、长路径 diff。
- 审批 sheet、用户提问、额度状态。
- 200% 字号和横屏。

### 发布硬门槛

arm64 release APK 真机完成：

- 下载→安装→登录→新建项目→修改文件→执行命令→恢复历史。
- 锁屏 15 分钟，回前台后状态准确。
- 网络切换、低内存、服务被杀、子进程被杀。
- 16 KiB 页执行验证。
- 停止后无持续运行的遗留命令。
- 谨慎模式确有符合文案的审批行为。
- 日志和分享中不出现凭据、代理口令或设备码。

## I. 风险清单与回退方案

**结论：最高优先级是“能否可靠执行”和“权限文案是否真实”，其次才是界面与性能。**

| 风险 | 级别 | 回退 |
|---|---|---|
| target 28 在设备上被阻止或无法 exec | P0 | 评估 APK 内置 nativeLibraryDir 路线；仍保持本地执行，不默认改成云端 |
| seccomp 导致 SIGSYS | P0 | 定位具体 syscall；若需修改/重编 Codex，则退出“直接使用官方二进制”路径 |
| `untrusted` 不能约束预期操作 | P0 | 撤掉谨慎模式宣传；不伪造“需要审批”的保证 |
| Agent 读取同 UID 凭据 | P0 边界 | 明示应用级隔离；严格隔离须重构执行架构 |
| helper 定位、shell、rg 不兼容 | P0/P1 | 启动自检；提供经过验证的工具包；能力缺失直接显示 |
| APK 内置路线无法保持 helper 名称/定位 | P0 | 验证 canonical path 查找逻辑；不能假定把两个文件改成 `.so` 名就一定可用 |
| 幽灵进程/厂商杀后台 | P1 | 限并发、前台服务、恢复状态；不自动重放任务 |
| experimental 协议变化 | P1 | 固定版本、版本适配层、实验升级、自检与回退 |
| 版本升级修改持久化格式 | P1 | 升级前静止备份状态；保留新版数据；避免覆盖用户升级后的项目修改 |
